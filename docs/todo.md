отдельно — зависимости указаны в таблице и внутри планов.

**Обязательно для исполнителя:** перед началом раздела прочитай `CLAUDE.md` целиком и
релевантные разделы `docs/HISTORY.md`, затем сам план из `docs/plans/`.

## Промт для агента-исполнителя

Скопируй, подставь номер раздела и путь к плану:

```text
Выполни раздел NN из docs/todo.md по плану docs/plans/NN-name.md.

Порядок работы:
1. Сначала прочитай CLAUDE.md целиком, релевантные разделы docs/HISTORY.md и весь план.
2. Выполняй план строго по этапам. Каждый этап — отдельный коммит; перед коммитом:
   целевые тесты, затем полный suite, затем git diff --check. Красный этап не коммить.
3. Если план противоречит реальному коду или чего-то в нём не хватает — не изобретай
   обход молча: реши минимально, а расхождение явно опиши в финальном отчёте.
4. Не трогай незакоммиченные изменения вне твоей задачи и не смешивай несвязанные правки.
5. Структуру Xcode-проекта меняй только через EditMD/project.yml + xcodegen generate.
6. По завершении: в docs/todo.md поставь разделу статус «сделано», в шапке плана обнови
   статус и отметь выполненные этапы.
7. Финальный отчёт: что сделано по этапам; решения, принятые сверх плана; что не сделано
   и почему; список того, что нужно проверить глазами в запущенном приложении
   (скриншоты снять нельзя — опиши шаги проверки).

Твой diff будет ревьюить другой агент: пиши читаемые коммиты, отклонения от плана
документируй, ничего не «чини» за пределами scope раздела.
```

### 01 — Правый сайдбар

Каркас правой панели (зеркало левой: resize, AppStorage, табы). Outline переезжает из левого
сайдбара направо; появляется вкладка Info (путь, размер, mtime, статистика, line endings,
git-статус, «скопировать путь»). Принцип разделения: слева — workspace-scope (Files, Tags,
Git), справа — document-scope.

### 02 — Ссылочный индекс

Фоновый индекс исходящих ссылок всех markdown-файлов workspace (wikilinks + относительные
markdown-ссылки) и обратная проекция (backlinks). Инкрементальное обновление при сохранении,
инвалидация по epoch как у `tagIndex`. Потребители: вкладки «Ссылки» и «Backlinks» в правом
сайдбаре (цель, контекст, строка, переход; неоднозначные и мёртвые цели помечаются),
счётчики связей в Info.

### 03 — Wiki-link UX

Автодополнение `[[` в Source и Visual (по именам файлов, title, aliases из индекса),
`[[Файл#Заголовок]]` — дополнение заголовков и скролл к заголовку при переходе, подсветка
неразрешённых wiki-links. Закрывает хвост «wiki-link autocomplete/heading scroll» из CLAUDE.md.

### 04 — Properties-панель

Frontmatter текущего документа как форма в правом сайдбаре: простые поля (string / number /
bool / date / list / tags / aliases) редактируются, сложный YAML помечается «Source only».
Правка меняет ровно одну строку YAML через обычный undoable-путь (обобщение механики
plugin-card из Preview). YAML-оформление уходит из основного потока документа в панель —
в главном окне остаётся только контент.

### 05 — История файла

Вкладка «История» в правом сайдбаре: bounded git-история файла + локальные ревизии
(content-addressed снапшоты при сохранении) + diff несохранённых изменений. Просмотр diff
любой ревизии, restore только через preview + подтверждение, откат — undoable-правкой
документа, не перезаписью файла.

### 06 — Vault-lint

Проверки уровня workspace поверх ссылочного индекса: мёртвый wikilink, ссылка на себя,
мёртвая относительная markdown-ссылка, файлы-сироты (никто не ссылается). Фоновый отчёт
по требованию; счётчик в Info.

### 07 — Поиск по workspace

Вкладка поиска в левом сайдбаре: полнотекстовый поиск по содержимому с синтаксисом фильтров
(`"фраза"`, `path:`, `tag:`, `type:`, `is:modified`, `after:`/`before:`), результаты с
контекстом и переходом к строке. Сортировки/представления «Недавние / Изменённые».

### 08 — Мелочи и доводка сайдбаров

Независимые небольшие фичи, каждая со своим мини-планом внутри общего файла: шаблоны при
создании файла (заметка, встреча, проект, daily), избранные файлы в Files, переезд Review
в правый сайдбар, callouts (`> [!note]`) во всех трёх режимах, индикатор line endings.
