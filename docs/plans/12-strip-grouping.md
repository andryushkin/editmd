## Диагноз (скриншот пользователя 2026-07-22 + код)

Скриншот: широкое окно без сайдбаров, Visual. Видимые группы обрываются на Quote,
Insert и Cleanup свёрнуты в «…» — при этом между колодцем и mode-switch пустует
больше трети окна.

| Факт в коде (`EditorActionStrip.swift`) | Проблема на экране |
| --- | --- |
| Не-split: `stripTrail = fieldTrail = max(field.textTrailing, barPaddingH)`, где `textTrailing` = margin центрированной колонки + `insetH` | Лента инструментов обрезается по правому краю **колонки текста**, а не по mode-switch. На широком окне справа мёртвая зона, группы сворачиваются «при куче места». В split правило уже правильное (`stripTrail = barPaddingH`) — расхождение веток |
| Все группы в одном колодце `quaternarySystemFill`; между кластерами только `groupSpacing = 8`, внутри кластера spacing 0 | Ряд читается как одна плоская лента из 14 кнопок; семантические группы (они есть в коде: inline / headings / lists / insert / cleanup) глазом не считываются |
| Overflow одноступенчатый: группа либо видна целиком, либо целиком падает в общий «…» (`plan(available:groups:)` — greedy слева направо) | Нет промежуточной ступени «группа сжалась в свою кнопку-сабменю со стрелочкой». Insert (5 контролов) исчезает целиком, хотя мог бы стать одной кнопкой-меню |

## Целевое поведение

### Состав и порядок групп (не меняется, фиксируем для ревью)

```
[123] | B I S <> == 🔗 │ H1 H2 H3 │ ≡• ☑ ≡1 ❝ │ 🖼 — </> ⊞(▾) ƒ▾ │ ◊▾ | …大 | [</> 📄 👁 ▣]
gutter  inline           headings    lists        insert            cleanup  mode-switch
```

- ⊞ — таблица: в Visual меню (▾: вставка + row/column ops), в Source/Split прямая кнопка.
- ƒ▾ — формула (меню из двух пунктов), ◊▾ — Cleanup (меню-ластик).
- В split после cleanup добавляется review, в preview — свой профиль (не трогаем).

### Три ступени раскладки (по убыванию ширины)

1. **Полная**: все группы развёрнуты. Лента занимает всё пространство от левого края
   поля (выравнивание по тексту/гаттеру сохраняется) до mode-switch — правая граница
   больше НЕ привязана к колонке текста.
2. **Компактная**: когда полная не влезает, группы по одной сжимаются в кнопку-сабменю
   со стрелочкой (это и есть «скрытая подгруппа»). Порядок сжатия — от наименее
   используемой: `insert` → `lists` → `headings`. Компактные представления:
   - insert → одна кнопка `plus` ▾ (меню: Image / Divider / Code Block / Table… /
     Formula…, вложенные секции как в текущем «…»);
   - lists → `list.bullet` ▾;
   - headings → текст-глиф `H` ▾ (пункты Heading 1–3, чек на активном уровне).
   `inline` и `cleanup` не компактятся: inline — самая частая группа, cleanup уже
   одна кнопка.
3. **«…» (последняя ступень)**: только если и компактная раскладка не влезает
   (сплит на минимальной ширине панели). Группы падают в общий «…» в обратном
   порядке важности: cleanup → insert → lists → headings → inline. Текущий
   механизм секций внутри «…» сохраняется.

### Видимые границы групп

Внутри общего колодца между группами — вертикальный hairline-разделитель
(`separatorColor`, высота ~60% высоты колодца), вместо нынешнего невидимого
`groupSpacing`. Один колодец сохраняется (решение спринта унификации: системный
accessory-стиль, без капсул на каждую группу) — разделители добавляют семантику,
не возвращая «панельки».

## Реализация

### 12.0 — Правая граница ленты: mode-switch, не колонка текста

`EditorActionStrip.body`: для не-split убрать `fieldTrail` из `stripTrail` — лента
всегда упирается в mode-switch (`SidebarChrome.barPaddingH`), как уже сделано для
split. Левая граница (`lead`) не меняется: выравнивание тулов по полю текста —
осознанное решение прошлых спринтов.

- Вынести вычисление ширины lane в pure static функцию
  (`resolvedToolLaneWidth(stripWidth:lead:modeWidth:)` рядом с существующей
  `resolvedEditingPaneWidth`) и покрыть тестами: широкое окно/узкое, split/не-split.
- Riski: preview-профиль (там `textLeading == nil` и lane считается из
  `previewRailWidth`) — проверить, что тема-кнопка не уехала; `.clipped()` на колодце
  остаётся страховкой.
- Проверка глазами: сценарий со скриншота (широкое окно без сайдбаров) — все пять
  групп развёрнуты, «…» отсутствует.

### 12.1 — Hairline-разделители групп

В `HStack` видимых пиллов между группами вставить разделитель (например,
`Rectangle().fill(Color(nsColor: .separatorColor)).frame(width: 1, height: 14)`),
изменение только в теле `EditorActionStrip` + measurement layer (разделитель входит
в измеряемую ширину группы или учитывается как константа в планировщике — решить
при реализации, главное чтобы `plan()` не начал врать на первом кадре).

- Dynamic color, обе темы; не запекать appearance.
- Проверка глазами: границы читаются, но не спорят с бордюром сегментов mode-switch.

### 12.2 — Двухступенчатый overflow (компактные подгруппы)

Ядро: планировщик из bool-логики «влезло/в …» превращается в выбор представления
на группу. Pure-функция (testable, `nonisolated static`):

```swift
enum GroupDisplay { case full, compact, overflow }
static func layoutPlan(available: CGFloat,
                       groups: [StripGroup],
                       fullWidths: [String: CGFloat],
                       compactWidths: [String: CGFloat]) -> [StripGroup: GroupDisplay]
```

Алгоритм: все full → пока не влезает, сжимать в compact по приоритету
(insert → lists → headings) → пока не влезает, сбрасывать в overflow
(cleanup → insert → lists → headings → inline). «…»-кнопка появляется только при
непустом overflow, её ширина учитывается как сейчас.

- Measurement layer измеряет оба представления: ключи `rawValue` и
  `rawValue + ".compact"` (компактные пиллы рендерятся скрыто так же, как сейчас).
- Компактные меню строятся из тех же `StripItem` (единая модель для пилла, compact-меню
  и «…» уже есть — `items(for:)`); вложенные Table/Formula внутри compact-insert —
  секциями, как в текущем «…».
- Хелпы компактных кнопок — существующие ключи «Headings» / «Lists» / «Insert»
  (уже переведены); новых строк по возможности ноль.
- Тесты: планировщик — граничные случаи (ровно влезает; влезает только с одной
  компактной; ничего не влезает → всё в overflow; нулевые измерения первого кадра →
  все full, как сейчас).

### 12.3 — Подгонка по глазам

Порядок групп, ширина разделителей, иконки компактных пиллов, пороги — финальная
сверка пользователем на трёх ширинах: широкое окно без сайдбаров / среднее окно с
двумя сайдбарами / split с панелью на минимуме. Плюс dark mode и ru-локаль.

## Контрольный лист приёмки

- Широкое окно без сайдбаров: пять групп развёрнуты, разделители видны, «…» нет.
- Сжатие окна: сначала insert схлопывается в `plus`▾, затем lists, затем headings;
  inline остаётся кнопками до последнего.
- Split на минимальной ширине: «…» появляется, всё содержимое доступно через него.
- Preview-профиль не изменился (strike/highlight/review/theme).
- Активные состояния в компактных меню: чек на текущем уровне заголовка, активный
  вид списка.
- Round-trip состава: `toolIDs(for:)` возвращает тот же набор id во всех ступенях —
  ступень меняет представление, не состав.

## Открытые вопросы для ревьюеров

1. Иконка компактного insert: `plus` против `plus.square` против `tray.and.arrow.down` —
   что читается как «вставка объекта», не конфликтуя с «+» добавления review-метки?
2. Нужна ли компактная ступень для inline (например B▾ с меню из шести пунктов) на
   сверхузких панелях, или «…» достаточно?
3. Разделители: hairline против увеличенного spacing (12–16pt) без линий — что ближе
   к системному accessory-бару macOS 14+?
4. Стоит ли в компактном insert-меню показывать row/column ops таблиц (Visual), или
   компактный режим оставляет только вставки, а ops доступны из контекстного меню
   таблицы?
