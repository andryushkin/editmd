# План 12 — Группировка кнопок Action Strip: место, границы групп, двухступенчатый overflow

Статус: черновик v3 после второго агентского ревью (2026-07-22).
Ревью v1: 12.0 одобрен; hairline отклонён в пользу интервала; 12.2 одобрен при условии
полного контракта планировщика. Ревью v2.1: четыре обязательные правки (toggle-семантика
вместо Picker, flatten-тест дерева команд, запрет дублирования шорткатов, две константы
в формуле стоимости) + арт-решения (groupGap 12 / overflowGap 8, hairline окончательно
нет, compact headings — динамический глиф, lists адаптивные). Всё включено ниже.

Зависимости: поверх ревизии стрипа 6d15da6 + 486527a (Link-кнопка, группа Insert в обоих
режимах, Cleanup-меню). Scope — `EditorActionStrip`, его layout-планировщик и одна ручка
в `BarControls.swift` (`showsIndicator` у `AccessoryBarMenu`); состав кнопок и их действия
НЕ меняются (утверждены пользователем в ревизии) — меняется только раскладка, видимость
границ групп и поведение при нехватке ширины. **Инвариант плана: ширина окна никогда не
меняет набор доступных действий — только их представление.**

Общие требования: прочитать `CLAUDE.md` (раздел «Производительность и UI» — measurement
layer, запрет `objectWillChange` из `updateNSView`) и `docs/HISTORY.md` про спринт
унификации баров; сборка и тесты через `xcodebuild` из корня; каждый этап = отдельный
коммит + проверка глазами пользователя (screencapture недоступен). Новые user-facing
строки — с ru-переводом в `Localizable.xcstrings` (сборка сама нормализует каталог и
помечает осиротевшие ключи stale — это не регрессия).

## Решения по итогам ревью v1 (зафиксированы, не переоткрывать)

1. **Hairline-разделители исключены** (подтверждено ревью v2.1 — окончательно, без
   резервного варианта). Границы групп — межгрупповым интервалом. Причины: система уже
   рисует hover/on-поверхности кнопок; четыре вертикальные линии в маленьком колодце
   имитируют segmented control и спорят с настоящим mode-switch; проект уже удалял ручные
   hairline при переходе на `.accessoryBar`; по HIG для группировки достаточно proximity.
2. **Compact-кнопки — со системным menu indicator.** `AccessoryBarMenu` сейчас принудительно
   ставит `.menuIndicator(.hidden)` (`BarControls.swift:69`) — добавить параметр
   `showsIndicator: Bool = false`. Полные Table/Formula/Cleanup остаются без стрелки,
   компактные группы показывают системный индикатор (`menuIndicator(.visible)`).
3. **Компактное представление не режет действия.** Compact Insert содержит всё: Image,
   Divider, Code Block, подменю Table (Insert 3×3 + Add/Delete Row + Add/Delete Column,
   где row/column ops доступны — т.е. в Visual), подменю Formula (Inline, Block).
4. **Типографика подменю:** никаких многоточий в ярлыках раскрывающихся подменю
   (многоточие в macOS означает «команда запросит дополнительный ввод») — подменю
   обозначается системной стрелкой.
5. **Иконка компактного Insert:** `plus` + системный chevron (не `plus.square` — лишняя
   рамка внутри accessory-контрола; не `tray.and.arrow.down` — читается как импорт).
6. **Компактной ступени для inline нет** — самая частая группа; на крайних ширинах она
   уходит в общий «…» последней.

## Решения по итогам ревью v2.1 (зафиксированы, не переоткрывать)

1. **Toggle-семантика, не Picker.** Существующие команды — переключатели: повторный
   выбор уровня снимает заголовок (`setHeading`), списки и Quote — toggle, причём Quote
   может быть активен одновременно со списком. `Picker` навязывает единственный выбор и
   ломает повторный клик. State-пункты compact-меню — обычные строки с системным
   checkmark и toggle-поведением: в SwiftUI это `Toggle` внутри `Menu` (системный
   state-чекмарк, независимые состояния); ручная иконка-чекмарк у `Button` — только если
   `Toggle` в accessory-меню отрендерится нештатно.
2. **Инвариант состава доказывается тестом дерева, не только `toolIDs`.** Меню сейчас
   собираются отдельными `@ViewBuilder`-ветками — зелёный `toolIDs` не гарантирует, что
   реальное compact-меню не потеряло Add Column или Block Formula. Вводится testable
   дерево команд (см. контракт), full/compact/overflow строятся из него, и тест
   проверяет `flatten(full) == flatten(compact) == flatten(overflow)` для Source,
   Visual, Split и Preview.
3. **Шорткаты в стрип-меню не регистрируются.** Format-меню — единственный владелец
   `keyboardShortcut`; display-only подсказки в SwiftUI нет, а второй регистрирующий
   обработчик для toggle-команд — ненадёжный контракт. Идея Typora о показе хоткеев
   отклонена для этого плана (потребовала бы отдельного AppKit-механизма).
4. **Две константы расстояний, обе в формуле стоимости.** `groupGap = 12 pt` —
   семантическая граница между группами (14 преждевременно ест ширину на полосе 34 pt);
   `overflowGap = 8 pt` — связь с соседним служебным контролом («…», mode-switch).
   `modeGap` остаётся в расчёте lane, не в планировщике.
5. **Compact headings — вариант Б′: динамический глиф.** Кнопка показывает `H1`/`H2`/`H3`
   по активному уровню, вне заголовка — нейтральный глиф (`H` или `¶` — выбор глазами
   в 12.3); ширина резервируется по максимальному состоянию. Информативнее статичного
   `H`, спокойнее длинного текстового комбо «Параграф / Заголовок 2».
6. **Lists остаются адаптивными** (не всегда-меню): после исправления правой границы
   (12.0) места должно хватать; Typora держит список в меню из-за существенно более
   узкой композиции.

## Референс Typora — источник идей, не копирования (`docs/typora/`)

Пользователь приложил 11 скриншотов Typora (плавающая нижняя капсула:
`[Параграф ▾] │ B I </> 🔗 │ 🖼 ❝ список▾ │ …`). Что берём как идеи, что нет:

Главный урок Typora — не внешний вид, а грамматика: явный chevron означает меню,
активное состояние видно до клика, tooltip обучает синтаксису.

**Берём / адаптируем:**

1. **Статус до клика.** Комбо Typora («Параграф ▾» / «Заголовок 2 ▾») показывает стиль
   без раскрытия меню. Мы адаптируем принцип, не форму: компактный headings — динамический
   глиф `H1`/`H2`/`H3` (решение v2.1 №5); длинный текстовый лейбл отклонён как
   неспокойный и дёргающий ширину.
2. **Явный chevron = меню.** Компактные кнопки получают системный menu indicator
   (решение v1 №2) — как у Typora, где ▾ отличает меню от кнопки.
3. **Tooltip как мини-учебник синтаксиса**: подсказки Typora показывают живой markdown
   (`` `Code` ``, `[Hyperlink]()`, `> Quote`). У нас это уже частично так
   («Bold (**…**)») — в 12.3 довести до системы: каждый help-текст кнопки редакторских
   режимов включает синтаксис.

**Не берём (зафиксировано ревью, чтобы не предлагать повторно):**

- **Шорткаты в пунктах стрип-меню** — отклонено ревью v2.1 №3: display-only подсказки
  в SwiftUI нет, а второй регистрирующий обработчик toggle-команд ненадёжен; хоткеями
  владеет Format-меню.
- **Список всегда-меню** — отложено (решение v2.1 №6): у Typora другая, существенно
  более узкая композиция; у нас lists адаптивные.
- **Hairline-разделители** — у Typora работают в воздушной плавающей капсуле, наш
  колодец плотнее и ниже; отклонены дважды (v1 №1, v2.1).
- Плавающая нижняя капсула по центру: конфликтует с устоявшимся верхним стрипом,
  гаттером и полосой текущей строки; переезд бара — отдельное продуктовое решение
  вне плана 12.
- Смешивание в «…» переполнения с контекстными командами блока (вставить абзац
  до/после, копировать как HTML, удалить блок): у нас «…» — строго переполнение;
  контекстные команды живут в контекстном меню редактора.
- «Скрыть панель инструментов» из «…» — идея хорошая, но это настройка стрипа,
  не раскладка; кандидат в хвосты после плана (Settings или View-меню).

## Целевое поведение

### Состав и порядок групп (не меняется, фиксируем для ревью)

```
[123] | B I S <> == 🔗   H1 H2 H3   ≡• ☑ ≡1 ❝   🖼 — </> ⊞ ƒ   ◊ | (…) | [</> 📄 👁 ▣]
gutter  inline           headings   lists        insert         cleanup    mode-switch
```

- ⊞ — таблица: в Visual кнопка-меню (вставка + row/column ops), в Source/Split прямая
  кнопка; ƒ — формула (кнопка-меню из двух пунктов); ◊ — Cleanup (кнопка-меню-ластик).
  Эти полные меню остаются без стрелки-индикатора (как сейчас).
- В split после cleanup добавляется review; preview-профиль: strike/highlight (усечённая
  inline), review, theme.

### Политика планировщика — все семь групп

Ранги заданы глобально; в каждом режиме участвует своё подмножество групп, относительный
порядок сохраняется. `compressionRank` — порядок сжатия в compact (меньше — раньше),
`nil` — группа не компактится. `overflowRank` — порядок ухода в общий «…» (меньше — раньше).

| Группа | compact-представление | compressionRank | overflowRank |
| --- | --- | --- | --- |
| cleanup | нет (уже одна кнопка-меню) | — | 0 |
| theme | нет (уже одна кнопка-меню) | — | 1 |
| insert | `plus.square.dashed`▾ — меню: Image / Divider / Code Block / подменю Table / подменю Formula | 0 | 2 |
| lists | `list.bullet`▾ — toggle-пункты четырёх видов, системный checkmark на активных | 1 | 3 |
| headings | динамический глиф `H1`/`H2`/`H3`▾ (вне заголовка — нейтральный), toggle-пункты уровней 1–3 | 2 | 4 |
| review | нет (одна кнопка) | — | 5 |
| inline | нет (решение ревью №6) | — | 6 |

Терминальное состояние планировщика: все активные группы в overflow, в ленте только «…» —
оно обязано помещаться в любой lane шириной ≥ ширины «…»-кнопки; ниже этого порога
работает существующий `.clipped()` как последняя страховка.

### Три ступени раскладки (по убыванию ширины)

1. **Полная**: все группы развёрнуты. Лента занимает всё пространство от левого края поля
   (выравнивание по тексту/гаттеру сохраняется) до mode-switch — правая граница больше НЕ
   привязана к колонке текста.
2. **Компактная**: группы по одной сжимаются в кнопку-сабменю со стрелкой в порядке
   `compressionRank` (insert → lists → headings).
3. **«…»**: группы по одной уходят в общий «…» в порядке `overflowRank`
   (cleanup → theme → insert → lists → headings → review → inline). Секции внутри «…»
   сохраняются как сейчас.

## Контракт планировщика

`StripGroup` — `private`; чтобы планировщик был testable, вводится internal-модель
(отдельный файл или уровень `EditorActionStrip`, но вне private-типов):

```swift
struct StripLayoutItem {
    let id: String              // StripGroup.rawValue
    let fullWidth: CGFloat
    let compactWidth: CGFloat?  // nil → группа не компактится
    let compressionRank: Int?   // nil → не компактится
    let overflowRank: Int
}

enum StripGroupDisplay { case full, compact, overflow }

/// Результат упорядочен так же, как вход: порядок групп — часть UI-контракта.
static func layoutPlan(budget: CGFloat,
                       groupGap: CGFloat,
                       overflowGap: CGFloat,
                       overflowWidth: CGFloat,
                       items: [StripLayoutItem]) -> [(id: String, display: StripGroupDisplay)]
```

- **Бюджет.** Ширина lane (этап 12.0):
  `lane = stripWidth − lead − trailingInset − modeWidth − modeGap`, где
  `trailingInset = SidebarChrome.barPaddingH` (всегда, а не `fieldTrail`),
  `modeGap = 8`. `modeGap` — часть расчёта lane, в планировщик групп он не передаётся.
  Планировщику передаётся внутренний бюджет `budget = lane − 2 × toolWellPaddingH`.
- **Стоимость состояния** пересчитывается целиком на каждом шаге (не последовательным
  вычитанием — оно ошибается ровно на пороговой ширине); обе константы расстояний явные:
  `cost = Σ width(представление видимых групп) + groupGap × max(0, видимых − 1)
  + (overflow непуст ? overflowGap + overflowWidth : 0)`.
- **Алгоритм.** Все full → пока `cost > budget`, сжимать очередную по `compressionRank` →
  пока всё ещё `cost > budget`, переносить очередную в overflow по `overflowRank`.
  Детерминирован от ширины: measurement layer всегда рендерит оба представления каждой
  сжимаемой группы (ключи `rawValue` и `rawValue + ".compact"`), поэтому ширины стабильны
  и дрожание на пороге исключено конструктивно (приёмка всё равно проверяет ресайз).
- **Первый кадр** (нулевые измерения): все full, как в текущем `plan()`.

## Дерево команд — доказуемый инвариант состава

Меню сейчас собираются отдельными `@ViewBuilder`-ветками (`tableMenu`, `formulaMenu`,
compact-меню добавят ещё), а модель `StripItem` плоская — зелёный `toolIDs`-тест не
гарантирует, что реальное меню не потеряло пункт. Вводится testable дерево:

```swift
struct StripCommandNode {
    let id: String                       // лист = id действия из toolIDs
    let children: [StripCommandNode]     // непусто → подменю (id узла не действие)
}

/// Единый источник: full-, compact- и «…»-представления группы строятся из ЭТОГО дерева.
static func commandTree(for mode: EditorMode, showTableOps: Bool) -> [StripCommandNode]
```

UI-рендер каждого представления обходит дерево (лист → кнопка/toggle-пункт, узел →
подменю); тест собирает листья каждого представления и проверяет:

`flatten(full) == flatten(compact) == flatten(overflow)` — для Source, Visual, Split
и Preview. Отдельно: листья дерева == `toolIDs(for:)` (две модели не расходятся).

## Реализация

### 12.0 — Правая граница ленты: mode-switch, не колонка текста

`EditorActionStrip.body`: для не-split убрать `fieldTrail` из `stripTrail` — лента всегда
упирается в mode-switch, как уже сделано для split. Левая граница (`lead`) не меняется.

- Вынести расчёт lane в pure static функцию со **всеми** участвующими метриками
  (`stripWidth`, `lead`, `trailingInset`, `modeWidth`, `modeGap`) и покрыть тестами:
  широкое/узкое окно, split/не-split.
- Риски: preview-профиль (`textLeading == nil`, lane считается из `previewRailWidth`) —
  проверить, что theme-кнопка не уехала; `.clipped()` остаётся страховкой.
- Проверка глазами: сценарий со скриншота — все пять групп развёрнуты, «…» отсутствует.

### 12.1 — Границы групп межгрупповым интервалом

Внутри колодца развести интервалы: внутри группы 0 (как сейчас), между группами
`groupGap = 12 pt` (арт-решение v2.1: 14 преждевременно ест ширину на полосе 34 pt);
к «…» и mode-switch — 8 pt (`overflowGap` / `modeGap`: 12 — семантическая граница,
8 — связь со служебным контролом). Никаких линий — окончательно.

- Обновить планировщик/measurement на обе константы (`groupGap` и `overflowGap`
  в `layoutPlan` — раздельные параметры).
- Docs: дописать в `docs/HISTORY.md` абзац о позднем решении «общий колодец под тулами»
  (сейчас оно живёт только в комментарии кода — ревью v1 споткнулось об это).
- Проверка глазами: группы читаются, колодец не превратился в подобие segmented control.

### 12.2 — Двухступенчатый overflow (компактные подгруппы)

- `BarControls.swift`: `AccessoryBarMenu(..., showsIndicator: Bool = false)`;
  `menuIndicator(.visible)` для compact-кнопок, остальные вызовы без изменений.
- Планировщик `layoutPlan` по контракту выше + сборка `[StripLayoutItem]` из активных
  групп режима (ранги — из таблицы политики).
- `commandTree(for:showTableOps:)` по контракту выше; full/compact/«…»-представления
  рендерятся обходом дерева, `@ViewBuilder`-ветки `tableMenu`/`formulaMenu` переводятся
  на него же.
- Активные состояния в compact-меню — toggle-пункты с системным checkmark (`Toggle`
  внутри `Menu`; решение v2.1 №1): повторный выбор снимает стиль, Quote и список могут
  быть отмечены одновременно. Не `Picker`.
- Шорткаты в пунктах стрип-меню НЕ регистрируются (решение v2.1 №3) — `keyboardShortcut`
  живёт только в Format-меню.
- Compact headings: динамический глиф `H1`/`H2`/`H3` по активному уровню, вне заголовка —
  нейтральный; ширина кнопки резервируется по максимальному состоянию, чтобы смена
  уровня не дёргала планировщик.
- Compact Insert: Image / Divider / Code Block / подменю Table (полный состав, включая
  row/column ops в Visual) / подменю Formula. Ярлыки подменю без многоточий.
- Measurement layer: измерять оба представления сжимаемых групп
  (`rawValue + ".compact"`), `controlSize` идентичен видимой ленте.
- Хелпы/ярлыки компактных кнопок — существующие ключи «Headings» / «Lists» / «Insert»
  (уже переведены); новых строк по возможности ноль.
- Тесты планировщика (граничные): ровно влезает всё full; влезает только с одной/всеми
  compact; ничего не влезает → всё в overflow (терминальное состояние); нулевые измерения
  → все full; **preview-профиль на узкой ширине** (theme → overflow раньше review, review
  раньше inline); порядок результата совпадает с порядком входа.
- Тест инварианта состава: `flatten(full) == flatten(compact) == flatten(overflow)`
  для всех четырёх режимов + листья дерева == `toolIDs(for:)`.

### 12.3 — Подгонка по глазам

Порядок групп, пороги сжатия, вид compact-кнопок — финальная сверка пользователем:
широкое окно без сайдбаров / среднее с двумя сайдбарами / split с панелью на минимуме /
полный Preview узкий. Плюс dark mode и ru-локаль.

- Нейтральный глиф компактного headings вне заголовка: `H` или `¶` — выбор глазами.
- Значения `groupGap = 12` / `overflowGap = 8` зафиксированы ревью; менять только если
  глаза пользователя скажут обратное (тогда — с записью решения в план).
- Если полная лента всё же кажется перегруженной — планировщик уже позволяет перевести
  lists в всегда-compact одним изменением рангов, но по умолчанию lists адаптивные
  (решение v2.1 №6).
- Довести help-тексты кнопок редакторских режимов до системы «подсказка = синтаксис»
  (`> Quote`, `[Link](…)` — как в Typora); сейчас так только у части кнопок.

Решения 12.3, принятые по глазам пользователя (реализованы):

- Терминальное состояние (всё в «…») показывает `textformat` + chevron + tooltip
  «Formatting Tools», а не голое «…».
- Гоча ×2: `.menuIndicator(.visible)` молча игнорируется под `.buttonStyle(.accessoryBar)`,
  а составной лейбл `Menu` AppKit-мост сплющивает до первого элемента (ручной chevron в
  лейбле тоже пропадает). Рабочее решение — chevron-бейдж в нижнем правом углу через
  `.overlay` СНАРУЖИ `Menu`; ширину измеряемого пилла не меняет.
- Компактный Insert — `plus.square.dashed` (голый `plus` не читался; выбор пользователя
  поверх арт-решения ревью v2.1 №5).
- Залипание активных состояний через смену режима закрыто сбросом `activeFormats` в
  `setEditorMode`; Source публикует heading/quote/codeBlock из cachedSpans.

## Контрольный лист приёмки

- Широкое окно без сайдбаров: пять групп развёрнуты, интервалы читаются, «…» нет.
- Сжатие окна: сначала insert схлопывается в `plus`▾, затем lists, затем headings; inline
  остаётся кнопками до последнего; появление «…» — только после исчерпания compact-ступени.
- Ресайз туда-обратно восстанавливает группы в стабильном порядке, без дрожания на пороге.
- Split на минимальной ширине панели: «…» появляется, всё содержимое доступно через него.
- Preview и Split проверяются на ширине, где review/theme вынуждены уйти в overflow.
- Набор действий во всех ступенях идентичен: `toolIDs(for:)` проверяет состав, тест
  дерева команд — `flatten(full) == flatten(compact) == flatten(overflow)` по четырём
  режимам, отдельный тест планировщика — представление и порядок.
- Compact-кнопки: chevron-бейдж в углу (системный menu indicator мёртв — см. гочу в
  «Решениях 12.3»), явный accessibility label, tooltip, keyboard focus.
- Активные Heading/List в compact-меню — toggle-пункты с системным checkmark; повторный
  клик снимает стиль; Quote и активный список отмечены одновременно.
- Compact headings показывает активный уровень в глифе; смена уровня не меняет ширину
  кнопки (резерв по максимальному состоянию).
- Light, Dark, Increase Contrast; английская и русская локали.
