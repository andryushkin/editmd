# План 12 — Группировка кнопок Action Strip: место, границы групп, двухступенчатый overflow

Статус: черновик v2.1 — v2 после агентского ревью + референс Typora (2026-07-22).
Вердикт ревью v1: 12.0 одобрен; 12.1 (hairline-разделители) отклонён — заменён на
межгрупповой интервал; 12.2 одобрен при условии полного контракта планировщика
(все семь групп, ordered-модель, полный состав compact-меню). Все условия включены ниже.

Зависимости: поверх ревизии стрипа 6d15da6 + 486527a (Link-кнопка, группа Insert в обоих
режимах, Cleanup-меню). Scope — `EditorActionStrip`, его layout-планировщик и одна ручка
в `BarControls.swift` (`showsIndicator` у `AccessoryBarMenu`); состав кнопок и их действия
НЕ меняются (утверждены пользователем в ревизии) — меняется только раскладка, видимость
границ групп и поведение при нехватке ширины. **Инвариант плана: ширина окна никогда не
меняет набор доступных действий — только их представление.**

Общие требования: прочитать `CLAUDE.md` (раздел «Производительность и UI» — measurement
layer, запрет `objectWillChange` из `updateNSView`) и `docs/HISTORY.md` про спринт
унификации баров; сборка и тесты через `xcodebuild` из корня; каждый этап = отдельный
коммит + проверка глазами пользователя (screencapture недоступен). Новые user-facing
строки — с ru-переводом в `Localizable.xcstrings` (сборка сама нормализует каталог и
помечает осиротевшие ключи stale — это не регрессия).

| Факт в коде (`EditorActionStrip.swift`) | Проблема на экране |
| --- | --- |

## Решения по итогам ревью v1 (зафиксированы, не переоткрывать)

1. **Hairline-разделители исключены.** Границы групп — межгрупповым интервалом 12–14 pt
   (проверить глазами). Причины: система уже рисует hover/on-поверхности кнопок; четыре
   вертикальные линии в маленьком колодце имитируют segmented control и спорят с настоящим
   mode-switch; проект уже удалял ручные hairline при переходе на `.accessoryBar`; по HIG
   для группировки достаточно proximity. Hairline — только резервный вариант Б, если
   интервал не сработает при визуальном сравнении.
2. **Compact-кнопки — со системным menu indicator.** `AccessoryBarMenu` сейчас принудительно
   ставит `.menuIndicator(.hidden)` (`BarControls.swift:69`) — добавить параметр
   `showsIndicator: Bool = false`. Полные Table/Formula/Cleanup остаются без стрелки,
   компактные группы показывают системный индикатор (`menuIndicator(.visible)`).
3. **Компактное представление не режет действия.** Compact Insert содержит всё: Image,
   Divider, Code Block, подменю Table (Insert 3×3 + Add/Delete Row + Add/Delete Column,
   где row/column ops доступны — т.е. в Visual), подменю Formula (Inline, Block).
4. **Типографика подменю:** никаких многоточий в ярлыках раскрывающихся подменю
   (многоточие в macOS означает «команда запросит дополнительный ввод») — подменю
   обозначается системной стрелкой.
5. **Иконка компактного Insert:** `plus` + системный chevron (не `plus.square` — лишняя
   рамка внутри accessory-контрола; не `tray.and.arrow.down` — читается как импорт).
6. **Компактной ступени для inline нет** — самая частая группа; на крайних ширинах она
   уходит в общий «…» последней.

## Референс Typora — источник идей, не копирования (`docs/typora/`)

Пользователь приложил 11 скриншотов Typora (плавающая нижняя капсула:
`[Параграф ▾] │ B I </> 🔗 │ 🖼 ❝ список▾ │ …`). Что берём как идеи, что нет:

**Берём / адаптируем:**

1. **Комбо-кнопка стиля абзаца с текстовым лейблом текущего состояния** («Параграф ▾» /
   «Заголовок 2 ▾»): одна кнопка и показывает статус, и меняет стиль; в меню — чекмарк
   на текущем и шорткаты. Для нас это кандидат-«вариант В» компактного headings
   (см. открытый вопрос 1): сильнее статичного «H»▾, но лейбл переменной ширины —
   резервировать ширину по самому длинному варианту, иначе дёргает планировщик.
2. **Шорткаты в пунктах меню.** Typora показывает ⌘1–⌘6 прямо в дропдауне. У нас
   ⌥⌘1…6 (заголовки) и ⌘L (bulleted list) уже существуют в Format-меню — пункты
   compact-меню обязаны нести те же `keyboardShortcut`, чтобы система показала хоткей
   (бесплатное обучение шорткатам). Включено в 12.2.
3. **Tooltip как мини-учебник синтаксиса**: подсказки Typora показывают живой markdown
   (`` `Code` ``, `[Hyperlink]()`, `> Quote`). У нас это уже частично так
   («Bold (**…**)») — в 12.3 довести до системы: каждый help-текст кнопки редакторских
   режимов включает синтаксис.
4. **Право списков быть всегда-меню.** У Typora список — одна кнопка-меню ▾ из трёх
   видов уже в ПОЛНОЙ ленте, не компактная ступень. Если в 12.3 полная лента покажется
   пользователю перегруженной — первый ход именно этот (lists всегда compact), он
   уже поддержан планировщиком без нового кода.
5. **Hairline-разделители в капсуле Typora работают** — датапоинт в пользу резервного
   варианта Б этапа 12.1. Решение v2 (интервал, линии — fallback) не переоткрываем:
   у Typora плавающая капсула с большим воздухом, наш колодец плотнее и ниже.

**Не берём (зафиксировать, чтобы ревьюеры не предлагали):**

- Плавающая нижняя капсула по центру: конфликтует с устоявшимся верхним стрипом,
  гаттером и полосой текущей строки; переезд бара — отдельное продуктовое решение
  вне плана 12.
- Смешивание в «…» переполнения с контекстными командами блока (вставить абзац
  до/после, копировать как HTML, удалить блок): у нас «…» — строго переполнение;
  контекстные команды живут в контекстном меню редактора.
- «Скрыть панель инструментов» из «…» — идея хорошая, но это настройка стрипа,
  не раскладка; кандидат в хвосты после плана (Settings или View-меню).

## Целевое поведение

### Состав и порядок групп (не меняется, фиксируем для ревью)

```
[123] | B I S <> == 🔗   H1 H2 H3   ≡• ☑ ≡1 ❝   🖼 — </> ⊞ ƒ   ◊ | (…) | [</> 📄 👁 ▣]
gutter  inline           headings   lists        insert         cleanup    mode-switch
```

- ⊞ — таблица: в Visual кнопка-меню (вставка + row/column ops), в Source/Split прямая
  кнопка; ƒ — формула (кнопка-меню из двух пунктов); ◊ — Cleanup (кнопка-меню-ластик).
  Эти полные меню остаются без стрелки-индикатора (как сейчас).
- В split после cleanup добавляется review; preview-профиль: strike/highlight (усечённая
  inline), review, theme.

### Политика планировщика — все семь групп

Ранги заданы глобально; в каждом режиме участвует своё подмножество групп, относительный
порядок сохраняется. `compressionRank` — порядок сжатия в compact (меньше — раньше),
`nil` — группа не компактится. `overflowRank` — порядок ухода в общий «…» (меньше — раньше).

| Группа | compact-представление | compressionRank | overflowRank |
| --- | --- | --- | --- |
| cleanup | нет (уже одна кнопка-меню) | — | 0 |
| theme | нет (уже одна кнопка-меню) | — | 1 |
| insert | `plus`▾ — меню: Image / Divider / Code Block / подменю Table / подменю Formula | 0 | 2 |
| lists | `list.bullet`▾ — меню четырёх видов, системный checkmark на активном | 1 | 3 |
| headings | текст-глиф `H`▾ — уровни 1–3, системный checkmark на активном | 2 | 4 |
| review | нет (одна кнопка) | — | 5 |
| inline | нет (решение ревью №6) | — | 6 |

Терминальное состояние планировщика: все активные группы в overflow, в ленте только «…» —
оно обязано помещаться в любой lane шириной ≥ ширины «…»-кнопки; ниже этого порога
работает существующий `.clipped()` как последняя страховка.

### Три ступени раскладки (по убыванию ширины)

1. **Полная**: все группы развёрнуты. Лента занимает всё пространство от левого края поля
   (выравнивание по тексту/гаттеру сохраняется) до mode-switch — правая граница больше НЕ
   привязана к колонке текста.
2. **Компактная**: группы по одной сжимаются в кнопку-сабменю со стрелкой в порядке
   `compressionRank` (insert → lists → headings).
3. **«…»**: группы по одной уходят в общий «…» в порядке `overflowRank`
   (cleanup → theme → insert → lists → headings → review → inline). Секции внутри «…»
   сохраняются как сейчас.

## Контракт планировщика

`StripGroup` — `private`; чтобы планировщик был testable, вводится internal-модель
(отдельный файл или уровень `EditorActionStrip`, но вне private-типов):

```swift
struct StripLayoutItem {
    let id: String              // StripGroup.rawValue
    let fullWidth: CGFloat
    let compactWidth: CGFloat?  // nil → группа не компактится
    let compressionRank: Int?   // nil → не компактится
    let overflowRank: Int
}

enum StripGroupDisplay { case full, compact, overflow }

/// Результат упорядочен так же, как вход: порядок групп — часть UI-контракта.
static func layoutPlan(budget: CGFloat,
                       spacing: CGFloat,
                       overflowWidth: CGFloat,
                       items: [StripLayoutItem]) -> [(id: String, display: StripGroupDisplay)]
```

- **Бюджет.** Ширина lane (этап 12.0):
  `lane = stripWidth − lead − trailingInset − modeWidth − modeGap`, где
  `trailingInset = SidebarChrome.barPaddingH` (всегда, а не `fieldTrail`),
  `modeGap = groupSpacing`. Планировщику передаётся внутренний бюджет
  `budget = lane − 2 × toolWellPaddingH`.
- **Стоимость состояния** пересчитывается целиком на каждом шаге (не последовательным
  вычитанием — оно ошибается ровно на пороговой ширине):
  `cost = Σ width(представление видимых групп) + spacing × (видимых − 1)
  + (overflow непуст ? spacing + overflowWidth : 0)`.
- **Алгоритм.** Все full → пока `cost > budget`, сжимать очередную по `compressionRank` →
  пока всё ещё `cost > budget`, переносить очередную в overflow по `overflowRank`.
  Детерминирован от ширины: measurement layer всегда рендерит оба представления каждой
  сжимаемой группы (ключи `rawValue` и `rawValue + ".compact"`), поэтому ширины стабильны
  и дрожание на пороге исключено конструктивно (приёмка всё равно проверяет ресайз).
- **Первый кадр** (нулевые измерения): все full, как в текущем `plan()`.

## Реализация

### 12.0 — Правая граница ленты: mode-switch, не колонка текста

`EditorActionStrip.body`: для не-split убрать `fieldTrail` из `stripTrail` — лента всегда
упирается в mode-switch, как уже сделано для split. Левая граница (`lead`) не меняется.

- Вынести расчёт lane в pure static функцию со **всеми** участвующими метриками
  (`stripWidth`, `lead`, `trailingInset`, `modeWidth`, `modeGap`) и покрыть тестами:
  широкое/узкое окно, split/не-split.
- Риски: preview-профиль (`textLeading == nil`, lane считается из `previewRailWidth`) —
  проверить, что theme-кнопка не уехала; `.clipped()` остаётся страховкой.
- Проверка глазами: сценарий со скриншота — все пять групп развёрнуты, «…» отсутствует.

### 12.1 — Границы групп межгрупповым интервалом

Внутри колодца развести интервалы: внутри группы 0 (как сейчас), между группами 12–14 pt
(новая константа, например `groupGap`; существующий `groupSpacing = 8` остаётся для
зазоров к «…» и mode-switch, если глазами не решится иначе). Никаких линий.

- Обновить планировщик/measurement на новую константу (spacing в `layoutPlan` = `groupGap`).
- Вариант Б (hairline) — только если интервал по глазам не даёт группировки; сравнение
  делает пользователь на этом этапе.
- Docs: дописать в `docs/HISTORY.md` абзац о позднем решении «общий колодец под тулами»
  (сейчас оно живёт только в комментарии кода — ревью v1 споткнулось об это).
- Проверка глазами: группы читаются, колодец не превратился в подобие segmented control.

### 12.2 — Двухступенчатый overflow (компактные подгруппы)

- `BarControls.swift`: `AccessoryBarMenu(..., showsIndicator: Bool = false)`;
  `menuIndicator(.visible)` для compact-кнопок, остальные вызовы без изменений.
- Планировщик `layoutPlan` по контракту выше + сборка `[StripLayoutItem]` из активных
  групп режима (ранги — из таблицы политики).
- Compact-меню строятся из тех же `StripItem` (`items(for:)` — единая модель для пилла,
  compact-меню и «…»); активные состояния — системный checkmark: headings/lists compact
  через `Picker(.inline)` с текущим значением (по образцу `themeMenu`), а не смена иконки.
- Пункты compact-меню показывают существующие хоткеи (заголовки ⌥⌘1…3, bulleted list
  ⌘L — как в Format-меню; идея Typora). Осторожно: display-only подсказки в SwiftUI
  нет, `.keyboardShortcut` на пункте стрип-меню РЕГИСТРИРУЕТ шорткат вторым — действие
  то же самое, но конфликт с Format-меню надо проверить руками; при двойном
  срабатывании/бипе — отказаться от показа хоткеев в стрипе, оставив их Format-меню.
- Compact Insert: Image / Divider / Code Block / подменю Table (полный состав, включая
  row/column ops в Visual) / подменю Formula. Ярлыки подменю без многоточий.
- Measurement layer: измерять оба представления сжимаемых групп
  (`rawValue + ".compact"`), `controlSize` идентичен видимой ленте.
- Хелпы/ярлыки компактных кнопок — существующие ключи «Headings» / «Lists» / «Insert»
  (уже переведены); новых строк по возможности ноль.
- Тесты планировщика (граничные): ровно влезает всё full; влезает только с одной/всеми
  compact; ничего не влезает → всё в overflow (терминальное состояние); нулевые измерения
  → все full; **preview-профиль на узкой ширине** (theme → overflow раньше review, review
  раньше inline); порядок результата совпадает с порядком входа.

### 12.3 — Подгонка по глазам

Порядок групп, значение `groupGap` (12 против 14), пороги сжатия, вид compact-кнопок —
финальная сверка пользователем: широкое окно без сайдбаров / среднее с двумя сайдбарами /
split с панелью на минимуме / полный Preview узкий. Плюс dark mode и ru-локаль.

- Если полная лента кажется перегруженной — первый ход: lists всегда compact
  (Typora-паттерн, поддержан планировщиком без нового кода); второй кандидат —
  headings-комбо (вопрос 1).
- Довести help-тексты кнопок редакторских режимов до системы «подсказка = синтаксис»
  (`> Quote`, `[Link](…)` — как в Typora); сейчас так только у части кнопок.

## Контрольный лист приёмки

- Широкое окно без сайдбаров: пять групп развёрнуты, интервалы читаются, «…» нет.
- Сжатие окна: сначала insert схлопывается в `plus`▾, затем lists, затем headings; inline
  остаётся кнопками до последнего; появление «…» — только после исчерпания compact-ступени.
- Ресайз туда-обратно восстанавливает группы в стабильном порядке, без дрожания на пороге.
- Split на минимальной ширине панели: «…» появляется, всё содержимое доступно через него.
- Preview и Split проверяются на ширине, где review/theme вынуждены уйти в overflow.
- Набор действий во всех ступенях идентичен: `toolIDs(for:)` проверяет состав (тест уже
  есть), отдельный тест планировщика — представление и порядок.
- Compact-кнопки: системный menu indicator, явный accessibility label, tooltip,
  keyboard focus.
- Активные Heading/List в compact-меню — системный checkmark (Picker), не смена иконки.
- Light, Dark, Increase Contrast; английская и русская локали.

## Открытые вопросы для ревьюеров

1. Компактное представление headings — три варианта по нарастанию информативности:
   А) статичный «H»▾ (дефолт v2); Б) активный уровень в глифе («H2»▾); В) Typora-комбо
   с текстовым лейблом стиля («Параграф ▾» / «Заголовок 2 ▾» — см. референс). Б и В
   дают статус без раскрытия меню, но лейбл переменной ширины дёргает планировщик —
