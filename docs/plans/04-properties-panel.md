# План 04 — Properties-панель: frontmatter-форма и YAML

Статус: сделано
Зависимости: 01 (правый сайдбар)

## Цель

Вкладка «Свойства» в правом сайдбаре: YAML frontmatter текущего документа как форма.
Простые поля редактируются контролами; сложные показываются read-only с пометкой
«Source only». Принцип (заимствован из raytsystem): **правка меняет ровно одну строку
YAML**, никогда не пересериализует весь frontmatter — комментарии, порядок ключей и
неизвестные поля сохраняются байт-в-байт.

Вместе с этим YAML-карточки уходят из основного потока: frontmatter в Visual/Preview
по умолчанию свёрнут (механика сворачивания уже есть), а редактирование живёт в панели.
В главном окне остаётся только контент документа.

## Контекст и существующий код

Прочитай: `CLAUDE.md` (плагины, frontmatter, `.raw`), `docs/HISTORY.md` (frontmatter,
plugin-card, сворачивание).

- `EditMD/EditMD/Editor/Frontmatter.swift` — база всего:
  `frontmatterRange(in:) -> FrontmatterRange` (full/body NSRange),
  `FMProperty` (key/value/items), `parseFrontmatterProperties(_:)`,
  `yamlLineSegments` (подсветка). Парсер уже отличает простые строки от сложных
  (комментарии, flow-списки, block-списки) — форма строится на нём.
- **Plugin-card в Preview** — главный прецедент: настройки активного плагина меняют
  registry-whitelisted поля frontmatter «через обычный undo path». Найди эту механику
  (грепай `BuiltInPluginRegistry`, применение правок frontmatter из Preview) и обобщи её:
  сейчас она whitelist-полей плагинов, нужна для произвольных **простых** полей.
- `EditMD/EditMD/Editor/BuiltInPlugins.swift` — registry; поля плагинов, которые уже
  редактируются карточкой, должны продолжить работать (двойной UI допустим: карточка в
  Preview остаётся, панель — новый путь к тем же полям).
- Инвариант CLAUDE.md: display-текст frontmatter-острова может отличаться, сериализатор
  читает payload `.raw`; сворачивание frontmatter — только presentation state.
- `EditMD/EditMD/Views/InspectorSidebar.swift` (после плана 01) — место монтирования.
- Undo: правка из панели должна попадать в undo-стек **активного редактора** документа и
  синхронно отражаться в Source/Visual/Preview (это обычная правка markdown-строки).

## Архитектурные решения

- **Ядро — чистые функции** в `Editor/FrontmatterEdit.swift` (новый файл):

  ```swift
  /// Заменяет значение простого поля key новой скалярной строкой.
  /// Возвращает новый полный текст документа или nil, если поле нельзя
  /// править безопасно (комментарий на строке, multiline, сложное значение).
  func replaceFrontmatterScalar(document: String, key: String, newValue: String) -> String?
  /// Добавляет поле в конец frontmatter (или создаёт frontmatter, если его нет).
  func insertFrontmatterScalar(document: String, key: String, value: String) -> String
  /// Удаляет строку простого поля.
  func removeFrontmatterField(document: String, key: String) -> String?
  /// Для tags/aliases/list: пересобирает ровно строки этого поля (flow или block —
  /// сохраняется исходный стиль).
  func replaceFrontmatterList(document: String, key: String, items: [String]) -> String?
  ```

  Все — построчные операции над исходным текстом, без YAML-сериализатора. Строка с
  trailing-комментарием: **значение** заменяется, комментарий сохраняется; если это
  ненадёжно (кавычки/экранирование) — поле помечается Source only. Лучше честный отказ,
  чем молчаливая порча.
- Типизация поля для формы (расширение `FMProperty` или обёртка `PropertyField`):
  `string / number / bool / date (YYYY-MM-DD) / tags / aliases / list / complex`.
  Определение типа — эвристика по значению; неоднозначное — string. `complex` → read-only.
- Экранирование: значения с `: `, `#`, ведущими/замыкающими пробелами и кавычками
  записываются в двойных кавычках с YAML-экранированием; функция + тесты. Значение,
  которое нельзя выразить одной строкой, — отказ (nil).
- UI-вкладка `"properties"` в InspectorSidebar: список полей key → контрол
  (TextField / Toggle / DatePicker / tags-редактор чипами), кнопка «+ поле» (имя + тип),
  у complex-полей бейдж «Source only» и кнопка «Открыть в Source» (переключить режим и
  поставить каретку на строку поля).
- Применение правки: `новыйТекст = replaceFrontmatterScalar(...)` → правка документа тем же
  путём, каким plugin-card применяет свои изменения (undoable, регистрируется как обычная
  локальная правка, не как внешнее изменение). Никаких прямых записей в файл.
- Коммит значения — по Enter/blur, не на каждый символ (иначе undo-стек засоряется).
- Frontmatter отсутствует → панель показывает «+ добавить свойства» (создаёт блок).
- Дефолтное сворачивание: после появления панели frontmatter в Visual и Preview по
  умолчанию свёрнут (только default-состояние; текущая механика disclosure сохраняется).
  Это отдельный этап и отдельный коммит — поведенческое изменение, о нём сказать
  пользователю явно.

## Этапы

1. **FrontmatterEdit.swift + тесты** — вся построчная механика, без UI. ✅
2. **Обобщение undoable-пути** — извлечь из plugin-card применение «нового текста
   документа» в общий helper (если он ещё не общий); plugin-card переводится на него же. ✅
3. **UI вкладки**: read-only отображение всех полей (включая complex) + бейджи. ✅
4. **Редактирование**: контролы по типам, «+ поле», удаление поля, tags/aliases чипами. ✅
5. **Сворачивание по умолчанию** в Visual/Preview + пункт настройки (если просится). ✅
   (дефолт collapsed; отдельный Settings-toggle не добавлялся — disclosure остаётся session-local)

Каждый этап — отдельный коммит, сборка и тесты зелёные.

## Тесты

Ядро (важнейшее — байтовая точность):

- Замена скаляра: сохраняются порядок ключей, отступы, пустые строки, комментарии
  (отдельной строкой и trailing), неизвестные поля, CRLF-документ.
- Отказы (nil): multiline-значение, block-структура, anchors/aliases, дубликат ключа,
  строка-комментарий с совпадающим префиксом ключа.
- Экранирование: `title: a: b`, `#` в значении, кавычки, кириллица/эмодзи, пробелы.
- Списки: flow (`[a, b]`) сохраняет flow-стиль, block (`- a`) — block; пустой список.
- insert: документ без frontmatter, с frontmatter; remove: единственное поле
  (frontmatter НЕ удаляется целиком — остаётся пустой блок? реши и зафиксируй тестом:
  рекомендация — оставлять пустой блок, удаление блока только вручную в Source).
- Round-trip: после правки поля документ парсится обратно, тело документа байт-в-байт.
- Интеграция: правка из панели отражается в Source/Visual/Preview и откатывается ⌘Z;
  file watcher не считает её внешним изменением.

## Критерии приёмки

- Все простые поля читаются и редактируются; complex видны read-only с переходом в Source.
- Комментарии/порядок/неизвестные поля никогда не теряются (доказано тестами).
- Undo/redo работает; правка синхронна во всех трёх режимах.
- Поля плагинов из registry редактируются и панелью, и (по-прежнему) карточкой в Preview.
- Frontmatter по умолчанию свёрнут в Visual/Preview, disclosure-состояние живёт как раньше.

## Инварианты и запреты

- Никакого YAML-сериализатора и никакой пересериализации всего блока — только построчные
  замены. Не подключай сторонние YAML-библиотеки.
- `.raw` — source of truth; правка идёт через полный текст документа и обычный
  round-trip, не через прямую мутацию island payload.
- Whitelist-принцип Preview-карточки не ослабляется: WebKit по-прежнему не передаёт
  произвольные YAML paths — панель нативная, это её преимущество.
- Дебаунс/коммит по blur; не пиши в документ на каждый keystroke.
- `xcodegen generate` после новых файлов; коммиты по этапам.

## Верификация

Сборка/тесты (см. план 01). Глазами: файл с богатым frontmatter (комментарии, теги flow и
block, даты, неизвестные поля, сложная вложенная структура) — отредактировать каждое простое
поле, проверить `git diff` файла: меняются только ожидаемые строки. Проверить ⌘Z, все три
режима, обе темы.
