# План 02 — Ссылочный индекс workspace + вкладки Ссылки/Backlinks

Статус: не начат
Зависимости: 01 (правый сайдбар — место монтирования вкладок)
Разблокирует: 03 (wiki-link UX), 06 (vault-lint)

## Цель

Фоновый индекс связей между markdown-файлами workspace:

- **исходящие ссылки** каждого файла: wikilinks (`[[Цель]]`, `[[Цель|Метка]]`,
  `[[Цель#Заголовок]]`, `![[img.png]]`) и относительные markdown-ссылки
  (`[текст](путь.md)`), с номером строки и фрагментом контекста;
- **обратная проекция** (backlinks): кто ссылается на данный файл.

Потребители в этом разделе: вкладки «Ссылки» и «Backlinks» в правом сайдбаре и счётчики
связей в Info. Дальше на индекс встают автодополнение (план 03) и vault-lint (план 06).

## Контекст и существующий код

Прочитай: `CLAUDE.md`, `docs/HISTORY.md` (разделы про wiki-links, tagIndex, производительность).

- `EditMD/EditMD/Editor/WikiLink.swift` — `scanWikiLinks(in:)`, `parseWikiInner`,
  `MDWikiLinkPayload` (target/label/heading). **Единственный парсер wikilinks** — не пиши
  второй; если индексу нужно больше данных (номер строки), расширяй `WikiLinkMatch`.
- `EditMD/EditMD/Views/WikiLinkResolver.swift` — резолвер цели по именам файлов workspace
  (`resolve(_:) -> [URL]`, кэш с `invalidate()`), `resolveLocalLinkDestination`,
  `nearestVaultRoot`. Резолюция целей индекса обязана давать **те же результаты**, что клик
  по ссылке; идеально — переиспользовать `WikiLinkResolver`, а не дублировать ранжирование
  (`targetRank`).
- `EditMD/EditMD/Views/WorkspaceModel.swift` — образец инкрементального кэша:
  `tagIndex` + `tagIndexKey` (строки ~115–118, 362–390), сброс при смене workspace
  (~1029, 1067). LinkIndex живёт рядом и инвалидируется теми же событиями.
- `EditMD/EditMD/Views/TagsSidebar.swift` — `scanWorkspaceTags(roots:maxBytes:)`: образец
  фонового walk по workspace с фильтрами.
- `EditMD/EditMD/Document/DocumentStore.swift:197` — `DocumentRegistry`: собственный flush
  документа — точка инкрементального обновления индекса для сохранённого файла.
- Формулы/маскирование: ссылки внутри code fence и inline code не должны индексироваться —
  посмотри, как `MarkdownHighlighter` / `collectSpans` определяют code-контексты, либо
  используй `scanWikiLinks`, если он уже маскирует код (проверь тестами).
- Из памяти проекта: workspace бывает большим, Visual обязан работать на больших файлах —
  индексация не должна грузить main и читать гигантские файлы целиком.

## Архитектурные решения

- **Новый файл** `EditMD/EditMD/Views/LinkIndex.swift` (или `Editor/` — реши по месту:
  чистый скан — Editor, привязка к WorkspaceModel — Views; предпочтительно разнести:
  чистые функции скана в `Editor/LinkScan.swift`, состояние индекса в `Views/LinkIndex.swift`).
- Модель данных:

  ```swift
  struct OutgoingLink: Equatable, Sendable {
      enum Kind { case wiki, markdown, image }
      let kind: Kind
      let rawTarget: String        // как в тексте
      let heading: String?         // из [[Цель#Заголовок]]
      let label: String            // отображаемый текст
      let line: Int                // 1-based
      let context: String          // строка-источник, обрезанная ~160 символов
      let resolved: URL?           // nil = не разрешена
      let candidates: [URL]        // >1 = неоднозначна
  }
  ```

- Индекс: `[URL: [OutgoingLink]]` (по стандартизованным URL) + производный
  `backlinks: [URL: [(source: URL, link: OutgoingLink)]]`. Пересчёт backlinks — из
  outgoing, отдельно не сканируется.
- Полный скан — в фоне (`Task.detached` / существующий паттерн background refresh),
  результат публикуется на main. Файлы > 4 МБ пропускаются (в отчёт индекса — счётчик
  пропущенных). Ключ инвалидации — epoch workspace + список roots, как `tagIndexKey`.
- Инкрементально: после собственного flush документа пересканируется **только этот файл**,
  затем пересобирается затронутая часть backlinks. Внешние изменения (file watcher) и
  create/rename/move файлов — полная инвалидация (дёшево: скан заново в фоне).
- Резолюция: сначала точный относительный путь (для markdown-ссылок), затем
  `WikiLinkResolver` (для wiki). Сетевые (`://`, `mailto:`) и якорные (`#…`) ссылки
  в индекс не входят.
- UI: в `InspectorSidebar` два таба — `"links"` и `"backlinks"` (иконки в стиле
  navigatorToolbar). Строка: метка/цель, `путь:строка`, контекст (вторичный цвет,
  1–2 строки), клик — открыть цель (для backlinks — открыть источник и прыгнуть на строку;
  переход по строке уже умеет `onJump`/review-навигация — переиспользуй).
  Неразрешённая цель — серым с пометкой «не найдена», неоднозначная — раскрывающийся
  список кандидатов.
- Счётчики в Info (план 01) заменяются на реальные.

## Этапы

### Этап 1 — чистый скан файла

`Editor/LinkScan.swift`: `func scanOutgoingLinks(text: String) -> [OutgoingLink]`
(без резолюции — `resolved`/`candidates` пустые). Wiki — через `scanWikiLinks`,
markdown-ссылки — через существующий парсинг (`collectSpans` уже находит link spans —
проверь и переиспользуй; не пиши третий markdown-парсер). Код-контексты исключаются.
Полные unit-тесты (см. ниже) — этот этап без UI.

### Этап 2 — индекс workspace

`LinkIndex` (ObservableObject или поле WorkspaceModel — выбери то, что не раздует
WorkspaceModel; отдельный класс с weak-связью предпочтителен):

1. Полный фоновый скан с публикацией на main, ключ-epoch, лимит размера файла.
2. Резолюция целей + backlinks-проекция.
3. Инкрементальное обновление из flush-пути DocumentRegistry (только правки через
   собственный save; критично не перепутать с внешними изменениями).
4. Инвалидация: смена workspace, create/rename/move/delete, внешнее изменение.

### Этап 3 — вкладки UI

1. Таб «Ссылки»: список исходящих активного документа. Для **несохранённого** буфера —
   пересканируй текущую строку документа напрямую (дёшево, один файл), чтобы вкладка не
   отставала от текста; резолюция — через индекс.
2. Таб «Backlinks»: список входящих по данным индекса, с пометкой «индекс обновляется…»
   пока фоновый скан не завершён.
3. Счётчики в Info.
4. Lite-окно без workspace: «Ссылки» работают (скан одного файла + резолюция относительных
   путей от папки файла), «Backlinks» показывают заглушку «нужен workspace».

## Тесты

- `scanOutgoingLinks`: все формы wiki (`[[A]]`, `[[A|B]]`, `[[A#H]]`, `![[img.png]]`),
  markdown-ссылки относительные/абсолютные/сетевые/mailto/якорные, ссылки внутри
  code fence и inline code (не индексируются), несколько ссылок в одной строке,
  UTF-16 (эмодзи/кириллица в целях и контексте), CRLF.
- Резолюция: точное совпадение, по имени без расширения, неоднозначность (два файла с
  одним именем в разных папках), отсутствие цели, `#Заголовок` не ломает резолюцию.
- Backlinks-проекция: A→B даёт B←A; правка A убирает/добавляет строки B; rename цели
  делает ссылку неразрешённой после реиндекса.
- Инкрементальность: после «flush» одного файла индекс других файлов не пересчитан
  (проверяемо через счётчик сканов в тестовом хуке).
- Perf-smoke: сгенерировать 500 файлов × 50 ссылок во временной папке — полный скан
  укладывается в разумное время (< пары секунд) и не на main.

## Критерии приёмки

- Вкладки Ссылки/Backlinks показывают корректные списки с контекстом и переходом.
- Клик по backlink открывает источник и позиционирует на строку ссылки.
- Правка + сохранение файла обновляют обе вкладки без полного рескана workspace.
- Мёртвые и неоднозначные ссылки видны и различимы.
- Нет фризов UI при первом открытии большого workspace (индекс строится в фоне).

## Инварианты и запреты

- Никакого disk I/O на main; публикация результатов — на main.
- Один парсер wikilinks (`WikiLink.swift`) и один резолвер (`WikiLinkResolver`) на всё
  приложение — расширяй их, не дублируй.
- Правки агента идут через `DocumentRegistry.applyAgentEdit` — инкрементальный хук индекса
  должен срабатывать и для них (это тот же flush-путь; проверь).
- `xcodegen generate` после добавления файлов; тесты кладутся в `EditMD/EditMDTests/`.
- Индекс — presentation/derived state: он никогда не меняет документы.

## Верификация

Сборка/тесты как в плане 01. Глазами (руками пользователя): workspace `docs/` самого
репозитория — открыть `docs/todo.md`, увидеть исходящие ссылки на планы; открыть план —
увидеть backlink на todo.md; сломать ссылку — увидеть «не найдена».
