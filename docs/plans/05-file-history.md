# План 05 — История файла: git + локальные ревизии + restore

Статус: не начат
Зависимости: 01 (правый сайдбар)

## Цель

Вкладка «История» в правом сайдбаре для текущего документа:

1. **Git-история файла** — bounded список коммитов, трогавших файл.
2. **Локальные ревизии** — снапшоты, которые EditMD пишет сам при сохранении: история
   есть даже без git и между коммитами.
3. **Несохранённые изменения** — diff текущего буфера против версии на диске.
4. **Просмотр diff** любой ревизии против текущего состояния и **restore** — только через
   preview + подтверждение, откат выполняется undoable-правкой документа, не перезаписью
   файла на диске.

## Контекст и существующий код

Прочитай: `CLAUDE.md` (Git, review/diff, autosave/flush), `docs/HISTORY.md` (git-подсистема,
diff approval).

- `EditMD/EditMD/Views/GitSidebar.swift`, `GitUI.swift` — как проект запускает git
  (Process в фоне, не на main) и парсит вывод. Новые git-вызовы — тем же паттерном.
- `EditMD/EditMD/Editor/GitCommitWatcher.swift` — обновление после коммитов; история
  должна инвалидироваться от него же.
- `EditMD/EditMD/Editor/TextDiff.swift` — построчный diff; переиспользуй для отображения
  (полный diff не на main — инвариант).
- `EditMD/EditMD/Editor/LineChangeTracker.swift` — существующая механика изменённых строк.
- `EditMD/EditMD/Integration/` — diff approval для `openDiff` (blocking tool): есть готовое
  UI сравнения двух версий; посмотри, что из него переиспользуемо для просмотра ревизий
  (view сравнения, стили). Не ломай его контракт.
- `EditMD/EditMD/Document/DocumentStore.swift` — `DocumentRegistry` (строка ~197): flush-путь
  (autosave) — точка записи локальных ревизий; «собственный flush обновляет `knownModDate`».
- **Имя занято:** `Views/DocumentHistory.swift` — это Back/Forward по окнам. Новые типы
  назови `FileRevisionStore` / `FileHistoryModel`, файл — `Views/FileHistorySidebar.swift`,
  стор — `Document/FileRevisionStore.swift`.

## Архитектурные решения

### Локальные ревизии

- Content-addressed store:
  `~/Library/Application Support/EditMD/revisions/<sha256(канонический-путь)>/`
  - `manifest.json` — массив записей `{contentSHA, savedAt, byteSize, label?}`
    (append-only, новые в конец);
  - `objects/<contentSHA>` — сами байты (markdown; без сжатия в v1).
- Запись: из flush-пути DocumentRegistry, **в фоне**, с дебаунсом — не чаще одной ревизии
  в N минут на файл (N = 5, константа), плюс запись «последнее состояние» при закрытии
  документа. Дедуп по contentSHA: одинаковое содержимое не пишется повторно.
- Прюнинг при записи: максимум 100 ревизий на файл — старые удаляются (сначала записи из
  manifest, затем осиротевшие objects). Файлы > 4 МБ в store не пишутся (запись в manifest
  с пометкой skipped не нужна — просто пропуск).
- Rename/move файла историю не переносит в v1 (путь — ключ). Зафиксируй это ограничение
  комментарием и в HISTORY при финализации; перенос — возможное расширение через
  транзакции path-мутаций (см. недавний коммит «Harden path mutation transactions»).
- Store изолирован по workspace? Нет — глобальный по абсолютному пути: проще и работает
  для lite-окон.

### Git-история

- `git log --follow --max-count=50 --format=… -- <file>` + `git show <rev>:<relpath>` для
  содержимого выбранной ревизии. Оба — фоновые Process с таймаутом; результаты кэшируются
  по (repo HEAD, file). Не в git-репозитории — секция скрыта.
- Показывать: дату, короткий hash, первую строку сообщения, автора (имя, без email).

### UI

- Таб `"history"` в InspectorSidebar, три секции: «Не сохранено» (если буфер отличается от
  диска — строка со счётчиком ±, клик открывает diff), «Локальные ревизии», «Git».
- Клик по ревизии → лист/окно сравнения: две панели или unified diff (переиспользуй
  существующее diff-view из Integration, если оно отделимо; иначе простой unified список
  строк на базе TextDiff с внутренней прокруткой). Кнопки: «Скопировать старую версию»
  (в буфер обмена), «Восстановить…».
- «Восстановить…»: подтверждающий диалог с кратким описанием (дата ревизии, ±строк).
  Restore = замена всего текста документа через обычный undoable-путь правки (как paste
  всего документа): работает undo, сериализация, watcher не срабатывает. Файл на диске
  обновит обычный autosave/flush.
- Если документ изменился, пока diff открыт, — при подтверждении сверить, что текущий текст
  равен тому, от которого считался preview; иначе показать «документ изменился, обновите
  preview» (аналог expected-hash из raytsystem, но в памяти, без файловых блокировок).

## Этапы

1. **FileRevisionStore + тесты** — чистая часть: manifest, дедуп, прюнинг, лимит размера;
   работа с временной директорией в тестах. Без UI.
2. **Подключение к flush** — дебаунс-запись из DocumentRegistry (фон), запись при закрытии.
   Тест: два flush подряд с одинаковым текстом → одна ревизия.
3. **Git-обвязка** — log/show в фоне, кэш, инвалидация по GitCommitWatcher. Тесты на парсинг
   формата log (fixture-вывод).
4. **UI вкладки** — списки, «не сохранено», diff-просмотр.
5. **Restore** — диалог, проверка актуальности, undoable-замена.

## Тесты

- Store: append/дедуп/прюнинг/лимит; повреждённый manifest.json не роняет приложение
  (лог + пересоздание); конкурентные записи двух документов не мешают друг другу.
- Дебаунс: частые flush в пределах окна → одна ревизия; после окна → новая.
- Git-парсинг: fixture `git log`-вывода, включая сообщения с `|`/переносами
  (используй `%x00`-разделители в format).
- Restore: замена текста undoable (⌘Z возвращает), watcher не считает внешним изменением,
  проверка актуальности отклоняет устаревший preview.
- Diff несохранённого: буфер == диск → секции нет; буфер != диск → корректные счётчики.

## Критерии приёмки

- История видна для файла в git-репозитории и вне его (локальные ревизии).
- Diff любой ревизии открывается без фризов (большой файл — diff в фоне, спиннер).
- Restore восстанавливает содержимое, откатывается ⌘Z, не создаёт git-коммитов.
- Store не растёт бесконечно (прюнинг) и не пишет дубликаты.
- Приватность: ревизии не пишутся для файлов вне «настоящих» сохранений (например,
  untitled-документы без URL — пропускаются).

## Инварианты и запреты

- Disk I/O и Process — только в фоне; SwiftUI body ничего не читает с диска.
- Restore и любые правки документа — через обычный undoable-путь; никаких прямых записей
  в файл в обход DocumentRegistry (иначе watcher увидит «внешнее изменение»).
- `openDiff`-контракт Integration не менять (continuation ровно один раз).
- IDE/control-сервисы под XCTest не стартуют — store в тестах инициализируется с явным
  временным путём, не с реального Application Support.
- `xcodegen generate` после новых файлов; этапы — отдельными коммитами.

## Верификация

Сборка/тесты (см. план 01). Глазами: править файл несколько минут с паузами → в истории
появляются ревизии; сделать коммит → git-секция обновилась; restore старой ревизии → текст
вернулся, ⌘Z откатил restore; повторный restore после правки требует обновлённый preview.
