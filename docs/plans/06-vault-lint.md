# План 06 — Vault-lint: мёртвые ссылки и файлы-сироты

Статус: сделано
Зависимости: 02 (ссылочный индекс)

## Цель

Проверки уровня **workspace** (существующий `MarkdownLint` работает внутри одного файла):

| Правило | Серьёзность | Смысл |
|---|---|---|
| `deadWikiLink` | error | wikilink не резолвится ни в один файл |
| `ambiguousWikiLink` | warning | wikilink резолвится в несколько файлов |
| `selfWikiLink` | warning | wikilink указывает на собственный файл |
| `deadRelativeLink` | error | относительная markdown-ссылка ведёт в никуда или за пределы workspace |
| `deadImageLink` | error | локальная картинка (`![](…)`/`![[…]]`) не существует |
| `orphanFile` | info/warning | на markdown-файл никто не ссылается |
| `deadHeadingAnchor` | warning | `[[Файл#Раздел]]` — файл есть, заголовка нет (требует данных плана 03; если 03 не сделан — правило пропускается) |

Поверхности: отчёт по workspace (по требованию) + вливание per-file находок в существующий
lint текущего документа.

## Контекст и существующий код

Прочитай: `CLAUDE.md` (lint, производительность), `docs/HISTORY.md` (lint, status bar).

- `EditMD/EditMD/Editor/MarkdownLint.swift` — `LintRule`, `LintSeverity`, существующие
  правила и как они отображаются (status bar, подсветка). Vault-правила добавляются в тот
  же enum ИЛИ отдельным `VaultLintRule` — реши по тому, как lint-результаты доезжают до
  UI: если пайплайн один, расширяй `LintRule`; сорсовый линтер не должен начать требовать
  workspace.
- План 02: `LinkIndex` — единственный источник данных о ссылках. Vault-lint **не сканирует
  файлы сам** — только читает индекс. Если индексу не хватает данных (например, признак
  «файл вообще ни на кого не ссылается»), расширяй индекс.
- `EditMD/EditMD/Views/FolderInfo.swift` — `homeDocument(in:)`: README/index-файлы. Сироты:
  home-документы корней workspace исключаются из `orphanFile` (на README по определению
  могут не ссылаться).
- Preview/статус-бар: где сейчас показывается счётчик lint-находок — vault-счётчик не должен
  смешиваться с per-file счётчиком (разные значки/секции).

## Архитектурные решения

- **Чистое ядро**: `Editor/VaultLint.swift` —
  `func vaultLintFindings(index: LinkIndexSnapshot) -> [VaultLintFinding]`, где snapshot —
  immutable значение (Sendable), считается в фоне. `VaultLintFinding`:
  `{rule, severity, file: URL, line: Int?, message, targetSuggestion: URL?}`.
- `targetSuggestion`: для dead-ссылок — ближайший кандидат по имени (уже есть ранжирование
  в WikiLinkResolver), показывается как «возможно, имелся в виду …». Без автопочинки в v1.
- Запуск: кнопкой из UI отчёта + автоматически после завершения фонового пересчёта индекса
  (дёшево: чистая функция по данным в памяти). Никогда — на keystroke.
- UI отчёта: секция в левом сайдбаре НЕ добавляется (левый — навигация). Отчёт — в правом
  сайдбаре не живёт тоже (он document-scope). Решение: **отдельное окно/лист «Проверка
  workspace»**, вызывается из меню (например, View → «Проверить ссылки workspace») и из
  Info-вкладки (строка «Проблем в workspace: N → Показать»). Список: группировка по файлу,
  клик — открыть файл на строке.
- Per-file вливание: находки vault-lint для активного документа добавляются к обычным
  lint-находкам в существующем UI (status bar/подсветка), с тем же механизмом отображения.
  Дебаунс: при правке документа vault-часть обновляется от инкрементального обновления
  индекса (после сохранения), не в реальном времени — это осознанное отставание, задокументируй.
- Исключения: файлы > лимита индекса (4 МБ) не проверяются; в отчёте отдельная строка
  «пропущено файлов: N».

## Этапы

1. **VaultLint.swift + тесты** — все правила на синтетических снапшотах индекса. Без UI. ✅
2. **Прогон в фоне** — модель `VaultLintModel` (ObservableObject): подписка на обновления
   LinkIndex, публикация findings на main, счётчик для Info. ✅
3. **Окно отчёта** — список с группировкой, переходы, повторный прогон, счётчик пропущенных. ✅
4. **Per-file вливание** — находки активного файла в существующем lint-UI. ✅

## Тесты

- Каждое правило: позитив + негатив (живая ссылка не флагается).
- `orphanFile`: исключение home-документов, файл с единственной ссылкой на себя —
  и сирота, и selfWikiLink.
- `deadRelativeLink`: `../за-пределы.md`, `%20`-экранирование в путях, якорная ссылка
  `#внутри` (не флагается), сетевые (не флагаются).
- `targetSuggestion`: опечатка в имени даёт правильного кандидата.
- Снапшот с пропущенными файлами: правила не выдумывают находок про них.
- Интеграция: правка, убирающая мёртвую ссылку, после сохранения убирает находку.

## Критерии приёмки

- Отчёт по демо-workspace с намеренными поломками показывает все типы находок, переходы
  работают.
- В чистом workspace отчёт пуст, счётчик в Info — 0/скрыт.
- Прогон на workspace в ~500 файлов не блокирует UI.
- Существующий per-file lint не изменил поведения на документах без workspace (lite-окна).

## Инварианты и запреты

- Vault-lint читает только снапшот индекса; никакого собственного файлового скана.
- Никаких автоматических правок файлов; только отчёт и навигация.
- Счёт на main запрещён; findings — immutable значения.
- `xcodegen generate` после новых файлов; ядро и UI — отдельными коммитами.

## Верификация

Сборка/тесты (см. план 01). Глазами: создать в тестовой папке файлы с мёртвым wikilink,
опечаткой (проверить suggestion), сиротой, битой картинкой — прогнать отчёт, покликать
переходы, исправить одну проблему и увидеть, как находка исчезает после сохранения.
