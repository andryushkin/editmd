# План 07 — Поиск по workspace с фильтрами

Статус: сделано
Зависимости: жёстких нет (независим от 01–06); мягкая — 02 (фильтр `tag:` быстрее по
индексу, но работает и без него через `tagIndex`)

## Цель

Вкладка поиска в **левом** сайдбаре (workspace-scope): полнотекстовый поиск по содержимому
markdown-файлов с синтаксисом фильтров, результаты с контекстом и переходом к строке.

Синтаксис (подмножество raytsystem, осмысленное для нативного приложения):

| Пример | Смысл |
|---|---|
| `архитектура запрос` | все токены должны встретиться (AND, без учёта регистра) |
| `"точная фраза"` | фраза целиком |
| `path:docs/plans` | префикс относительного пути |
| `type:md` | расширение файла (по умолчанию ищем только md; `type:*` — все текстовые) |
| `tag:research` | тег из frontmatter (источник — существующий `tagIndex`) |
| `is:modified` | git-статус не clean (вне git — фильтр даёт пустой результат с пояснением) |
| `after:2026-07-01` / `before:…` | mtime файла |

Фильтры комбинируются; текстовые токены ищутся в содержимом и имени файла.

## Контекст и существующий код

Прочитай: `CLAUDE.md` (производительность, сайдбар), `docs/HISTORY.md` (sidebar, tagIndex).

- `EditMD/EditMD/Views/WorkspaceSidebar.swift` — добавление таба `"search"` в
  `navigatorToolbar` и `switch tab`. Нижний `filterText`-инпут — это фильтр **текущей
  вкладки**; у поиска своё поле запроса сверху вкладки, нижний filter к нему не относится
  (скрой его или оставь неактивным для search-таба — реши по месту и зафиксируй).
- `EditMD/EditMD/Views/WorkspaceModel.swift` — roots, `visibleFiles`, `tagIndex`, epoch;
  walk по файлам — по образцу `scanWorkspaceTags`.
- `EditMD/EditMD/Views/GitSidebar.swift` — источник git-статусов для `is:modified`
  (переиспользуй кэш, не запускай новый Process на каждый поиск).
- Переход к строке: `onJump`/механика Outline и Review (клик по находке = открыть файл +
  прыжок на строку).
- Открытие файлов — существующий роутинг (`onOpen` в сайдбаре), включая модалку «уже

## Архитектурные решения

- **Парсер запроса — чистая функция** `Editor/SearchQuery.swift`:
  `func parseSearchQuery(_ raw: String) -> SearchQuery` где `SearchQuery` — токены, фразы,
  фильтры. Неизвестный `ключ:` трактуется как обычный токен (мягкая деградация). Тесты — полные.
- **Исполнитель** `Views/WorkspaceSearchModel.swift` (ObservableObject):
  - поиск запускается по дебаунсу от ввода (300 мс) и отменяется при новом вводе
    (`Task` + cancellation check в цикле по файлам);
  - в фоне: сначала дешёвые фильтры (path/type/tag/dates/git) сужают список файлов, затем
    контент-скан оставшихся; файлы > 4 МБ пропускаются (счётчик в футере результатов);
  - контент читается потоково построчно; совпадение = все токены и фразы встречаются в
    файле (фразы — регистронезависимо); для показа собираются до 5 первых строк-совпадений
    на файл с номерами строк;
  - лимит результатов: 200 файлов, дальше «уточните запрос»;
  - без персистентного индекса в v1 — честный скан с кэшем прочитанного по (url, mtime)
    в памяти (LRU, ограничение по суммарному размеру ~64 МБ). Персистентный FTS —
    возможное будущее, в план не входит.
- **UI**: поле запроса (с подсказкой синтаксиса в placeholder/при пустом вводе — краткая
  шпаргалка фильтров), под ним — результаты: группировка по файлу (имя + путь), внутри —
  строки-совпадения с подсветкой совпавшего фрагмента; клик по строке — открыть + прыгнуть;
  футер: «N файлов · M пропущено · за T мс».
- **Сортировка результатов**: по релевантности не заморачиваемся в v1 — по числу совпадений,
  затем по mtime. Кнопка-переключатель «по дате».
- Поиск не трогает несохранённые буферы других окон — ищет по диску; для активного
  документа допустимо честно сказать в футере «несохранённые изменения не учитываются»
  (не реализовывать merge буферов).

## Этапы

1. ✅ **SearchQuery.swift + тесты** — парсер синтаксиса.
2. ✅ **Исполнитель + тесты** — matching-функции как чистые (`fileMatches(query, meta)`,

3. ✅ **UI вкладки** — таб, поле, результаты, переходы, футер.
4. ✅ **Git/tag-фильтры** — подключение `is:modified` к git-кэшу и `tag:` к `tagIndex`.

## Тесты

- Парсер: фразы с кавычками (в т.ч. незакрытая), несколько фильтров, `path:` с кириллицей
  и пробелами (в кавычках: `path:"мои заметки"`), неизвестный ключ, пустой запрос.
- Matching: AND-семантика, регистронезависимость (включая кириллицу — `localizedCaseInsensitive`
  или lowercased-сравнение, зафиксируй выбор), фраза через границу токенов, совпадение в
  имени файла без совпадения в теле.
- Даты: `after:`/`before:` границы включительно/исключительно — зафиксируй тестом.
- Отмена: новый запрос отменяет старый (тест через медленный фейковый провайдер файлов).
- Лимиты: >200 файлов, файл >4 МБ.

## Критерии приёмки

- Поиск по репозиторию EditMD (`docs/` + корень) находит ожидаемое, переходы работают.
- Набор запроса не подвешивает UI; результаты стабильно приходят после паузы ввода.
- Все фильтры работают и комбинируются; вне git `is:modified` даёт понятное пустое состояние.
- Повторный поиск того же запроса заметно быстрее (кэш).

## Инварианты и запреты

- Скан только в фоне, отменяемый; никакого чтения файлов из SwiftUI body.
- Никаких новых Process для git — только существующий кэш статусов.
- Не выноси поиск в правый сайдбар — он workspace-scope, живёт слева.
- `xcodegen generate` после новых файлов; парсер/исполнитель/UI — отдельные коммиты.
