Статус: сделано (2026-07-16)
Зависимости: указаны per-фича. Фичи независимы — можно брать по одной, каждая = отдельный

Общие требования ко всем фичам: прочитать `CLAUDE.md` и релевантные разделы

## 8.1 Шаблоны при создании файла ✅

Зависимости: нет.

Кнопка «Новый файл» предлагает шаблон: Пустой / Заметка / Встреча / Проект / Исследование /
Ежедневная заметка (daily: имя по дате `YYYY-MM-DD.md`).

- Шаблоны — встроенные Swift-константы (`Views/FileTemplates.swift`): frontmatter +
  скелет тела. Плейсхолдеры `{{date}}` (сегодня, `YYYY-MM-DD`), `{{title}}` (имя файла без
  расширения). Никакой загрузки шаблонов с диска/из сети в v1 (политика встроенных плагинов
  распространяется и сюда); пользовательские шаблоны — возможное расширение.
- Точка входа: текущий флоу «+» в левом сайдбаре (`FolderInfo.markdownFileName` валидация
  имени сохраняется). UI: подменю или диалог с выбором шаблона; «Пустой» — дефолт, Enter
  не должен стать медленнее для обычного сценария.
- Daily: если файл на сегодня существует — открыть его, не создавать дубликат.
- Тесты: рендер плейсхолдеров, дедуп daily, валидация имён не сломана.
- Приёмка: создание из каждого шаблона, frontmatter корректно парсится (панель свойств,
  если план 04 сделан), undo создания не требуется (файловая операция, как сейчас).

## 8.2 Избранные файлы ✅

Зависимости: нет.

Пин файлов в левом сайдбаре: секция «Избранное» над деревом Files.

- Контекстное меню файла: «В избранное» / «Убрать из избранного». Хранение — per-workspace
  (вместе с тем, где хранятся adopted roots — найди это место в WorkspaceModel/AppState и
  положи рядом), список URL, максимум 50.
- Файл исчез с диска → строка серым с пометкой, клик убирает из избранного (не молча).
- Rename/move через сайдбар обновляет закладку (хук в существующие path-мутации —
  см. «Harden path mutation transactions»).
- Тесты: персистентность, чистка исчезнувших, обновление при rename.

## 8.3 Переезд Review в правый сайдбар ✅

Зависимости: 01.

Review-метки — document-scope, по критерию разделения им место справа.

- Перенести `ReviewSidebar` из `switch` в `WorkspaceSidebar` в `InspectorSidebar`
  (тем же способом, что Outline в плане 01, включая миграцию `sidebarTab == "review"` →
  `inspectorTab = "review"` и правку всех программных открытий: минимум одно в
  ContentView — compose-форма review из Preview/Split, см. `sidebarTab = "review"`).
- Фильтр-инпут правой панели должен фильтровать и Review (как левый делал).
- Проверить FIFO-инварианты ReviewModel не задеты (переезд — чисто UI).
- Приёмка: полный review-цикл (создать метку, увидеть в панели, jump, resolve) из нового места.

## 8.4 Callouts (`> [!note]`) ✅

Зависимости: нет, но это самая тяжёлая фича раздела — **три пути рендера + round-trip**
(инвариант CLAUDE.md: Source=`collectSpans`, Visual=`VisualRenderer`, Preview=`HTMLBodyVisitor`).

Синтаксис (Obsidian-подмножество): первая строка цитаты `> [!note] Опциональный заголовок`,
типы v1: `note`, `tip`, `warning`, `important`, `example` (+ неизвестный тип рендерится
как `note` с сохранением имени). Без вложенных callout и без foldable (`[!note]-`) в v1.

- Source: подсветка маркера `[!type]` (display-only, байты не трогать).
- Visual: блок цитаты получает тип-специфичную презентацию (иконка + цвет полосы);
  `.raw`/round-trip: callout остаётся обычной цитатой в markdown — сериализация не должна
  измениться вообще (это чистая презентация цитаты, самый безопасный дизайн).
- Preview: HTML-класс + иконка + обе палитры (light/dark, dynamic).
- Тесты: round-trip файла с callout байт-в-байт; известный/неизвестный тип; callout внутри
  списка (если сложно — задокументированно не поддерживать, рендерить обычной цитатой).
- Приёмка: все три режима + Split, обе темы, round-trip зелёный, `testCorpusRoundTrip`
  не сломан (помни: `test-all-elements.md` — живая фикстура, сначала `git diff` файла).

## 8.5 Индикатор line endings и финального newline ✅

Зависимости: 01 (Info-вкладка уже показывает это статикой — см. план 01 этап 3).

Доводка: если файл CRLF или mixed, или без финального newline — в Info рядом с фактом
кнопка «Нормализовать» (LF + финальный newline) как **обычная undoable-правка** документа.

- Реализация: чистая функция `normalizeLineEndings(text:) -> String?` (nil = уже
  нормализован) + применение через обычный путь правки.
- Инвариант: без нажатия кнопки EditMD никогда не меняет line endings сам (сохранение
  как есть — проверь, что это сейчас так, и зафиксируй тестом).
- Тесты: CRLF→LF, mixed→LF, идемпотентность, undo.
