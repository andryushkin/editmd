# План 11 — Визуальный язык Visual-режима: типографика под Apple-стиль

Статус: черновик v2 после ревью пользователя (2026-07-22)
Зависимости: нет. Этапы строго по порядку — 11.0 задаёт меру строки и baseline, всё
дальнейшее калибруется под неё. Каждый этап = отдельный коммит + проверка глазами
пользователя (screencapture недоступен). Scope — только Visual: Source и Preview (со своей
системой тем `PreviewTheme`) не трогаем. PDF-экспорт строится через Preview HTML
(`PDFExporter` → `previewHTMLPage`) и планом не затрагивается; согласование Preview/PDF с
новым языком Visual — отдельная задача вне плана.

Общие требования: прочитать `CLAUDE.md` и разделы `docs/HISTORY.md` про Visual/round-trip;
сборка и тесты через `xcodebuild` из корня; `xcodegen generate` при новых файлах.

## Диагноз (скриншоты 2026-07-22 + код)

Текущий облик — имитация GitHub (`EditorTheme.github`, портирован из swift-markdown-ui).
Для нативного macOS-редактора это чужой язык: экранная типографика Apple строит иерархию
размером, жиром и воздухом, а не цветом и линиями.

| Факт в коде | Проблема на экране |
| --- | --- |
| Дефолт `columnWidth = 0` (full width) | Строка на широком окне неограниченна — leading и кегли невозможно откалибровать |
| Нет `lineSpacing`/`lineHeightMultiple` нигде в Visual — дефолтный leading SF | Плотный, «слипшийся» текст; абзацы читаются тяжело |
| Inline-код: красный `#d1242f`/`#ff7b72` + `.backgroundColor` серый (`VisualCoordinatorPresentation.swift:554`) | Красные пятна доминируют над контентом; фон — прямоугольник, некрасиво рвётся на переносе строки |
| Ссылки: accent + постоянный `underlineStyle` (`:543`) | Подчёркивание всего подряд — web-стиль, не Apple |
| H1/H2: линии-дивайдеры под заголовком (`headingDividerRanges`) | GitHub-изм; Apple заголовки не подчёркивает |
| Заголовки: before 14/10, after 8 — почти симметрично | Заголовок не «прилипает» к своему разделу (нужно before:after ≈ 2–3:1) |
| Маркеры списков, номера, чекбоксы — все accent-синие | Синий шум; в Notes/HIG маркеры нейтральные, акцент — только интерактив |
| Blockquote: синий бар + серый wash (`quoteBackground`) | Тяжёлая «плашка»; у Apple цитата — тонкий серый бар + приглушённый текст |
| Таблицы: рамка каждой ячейки 0.5pt + серая заливка header (native `NSTextTableBlock` и island-грид) | Excel/GitHub-сетка; Apple-таблицы — только горизонтальные hairlines |
| Битое/отсутствующее изображение — крошечный глиф U+FFFC | Выглядит как мусор (скриншот test-all-elements, стр. 90) |
| Выполненная задача: strikethrough + secondary | Двойное погашение; в Notes достаточно серого |

## Принятые решения (ревью 2026-07-22)

1. **Мера строки**: новый дефолт `columnWidth ≈ 740` (prose-колонка в стиле iA Writer/Craft);
   `0` (full width) остаётся доступен в Settings. Все ритм-числа калибруются под 740.
2. **Миграция**: жёсткая. Это редизайн — старые сохранённые значения типографики
   заменяются новыми, versioned-слияние со старыми overrides не делаем (детали в 11.0).
3. **Ссылки**: без постоянного подчёркивания, но цвет не может быть единственным
   отличием — обязательно минимум одно дополнительное состояние (11.3).
4. **Inline-код**: два шага — сначала нейтральный цвет + слабый плоский фон, pill только
   после просмотра плотного текста; финальный baseline один, perf-fallback не является
   вторым допустимым обликом (11.3).

## Целевая шкала (при базе 15 pt; всё × пользовательский `sizeScale`/`spacingScale`)

Иерархия — по мотивам HIG type ramp (Large Title 26 / Title 1 22 / Title 2 17):

| Элемент | Кегль | Вес | Line height | Before / after |
| --- | --- | --- | --- | --- |
| Body, списки, цитаты | 15 | regular | 1.30 (окно 1.28–1.32) | after 8 |
| H1 | ×1.75 ≈ 26 | bold | 1.12 (окно 1.10–1.16) | 26 / 8 |
| H2 | ×1.45 ≈ 22 | semibold | 1.12 | 22 / 7 |
| H3 | ×1.2 ≈ 18 | semibold | 1.12 | 16 / 6 |
| H4 / H5 | ×1.07 / ×1.0 | semibold | 1.18 | 12 / 5 |
| H6 | ×1.0 + `secondaryColor` | semibold | 1.18 | 12 / 5 |
| Код (inline и блочный) | моно ×0.88 ≈ 13 | regular | блок 1.20 (окно 1.18–1.22) | — |

**Оптические ограничения** (база настраивается 9–40 pt, шкала обязана выживать на краях):

- Моно-код: `max(base × 0.88, min(base, 11))` — не меньше 11 pt, но никогда крупнее body.
- Приращение заголовка капится в абсолютных pt: H1 ≤ base+16, H2 ≤ base+10, H3 ≤ base+6
  (на accessibility-размерах шкала сжимается — как в Dynamic Type).
- Обязательная проверка шкалы при базе 12, 15, 20 + sanity на краях 9 и 40.

Числа — стартовые значения, а не догма: после каждого этапа пользователь смотрит глазами
и числа подгоняются. Tracking не трогаем: `NSFont.systemFont` сам переключает оптические
размеры SF.

## Контрольный лист

Эталон приёмки — НЕ Apple Notes/Bear (они moodboard, не pass/fail), а собственный
контрольный файл `demo-typography.md` в корне репозитория (создаётся в 11.0, в традиции
`demo-tables.md`/`demo-pdf.md`). Обязательное содержимое:

- кириллица, смешанный русский/английский абзац, цифры и даты, emoji, длинные URL;
- многострочный H1 и H2 (2–3 строки при колонке 740);
- пары ритма: H1→H2 подряд, H2→H3, заголовок→список, список→заголовок, цитата→заголовок,
  заголовок первой строкой документа;
- плотный технический абзац с инлайн-кодом в каждой строке (по мотивам скриншота-1);
- таблица с числовой колонкой, датами и одной длинной ячейкой.

Условия просмотра фиксированные: окно 1000×800, columnWidth 740, база 15, spacing 1.0,
light и dark. Каждый этап принимается на этом файле при этих условиях (плюс свои
специфические проверки).

## Инварианты (обязательны на каждом этапе)

- **Presentation-only**: ни один этап не меняет байты markdown и сериализацию. Round-trip
  suite зелёный; plain string у storage до/после presentation pass идентичен.
- `test-all-elements.md` — живой файл-фикстура, app пишет в него на лету: его diff не коммитить.
- Все цвета — динамические `NSColor(name:)` light/dark; не запекать `NSApp.effectiveAppearance`.
- Константы — в `EditorTheme` (единственная baseline-тема после спринта 3); новую систему
  тем не строить. Настройки Settings (пикеры, слайдеры) продолжают работать поверх новых
  дефолтов.
- `MDBlock.hash` остаётся O(1); тяжёлые payload в значениях атрибутов не хешировать.
- Native-таблицы и island-грид имеют одинаковую иерархию и визуальные токены (константы
  общие); функционально они различаются, попиксельного совпадения не требуется.
- Split-режим (Source+Visual): sync-scroll не ломается от новых интервалов — проверять на
  узком Split.

## 11.0 Ширина строки, baseline и миграция настроек

Файлы: `EditorSettings.swift`, `SettingsView.swift` (если меняется дефолт слайдера),
новый `demo-typography.md`.

- Дефолт `ModeSettings.columnWidth` для Visual: 0 → 740 (механика reading column уже
  есть — `EditorSettings.swift:196`, диапазон 320–1400; `0` = full width остаётся опцией).
- Проверить жизнь широкого контента в колонке: native-таблицы (wrap ячеек уже умеет),
  island-таблицы (горизонтальный скролл грида работает при колонке), code blocks
  (длинные строки), формулы display-math. В v1 весь контент живёт внутри колонки; выпуск
  таблиц за колонку — отложенная идея, в план не входит.
- **Миграция (жёсткая, решение пользователя)**: поле `typographyVersion` в Visual-настройках.
  При загрузке `< 2`: `elements` (вся `ElementStyles` — размеры, веса, цвета) и
  `columnWidth` перезаписываются новыми дефолтами, ставится `2`. Личные `fontSize`,
  `insetH/insetV`, `bodyFamily` не трогаем. Reset Visual Settings даёт тот же результат.
  Зафиксировать поведение в `docs/HISTORY.md` — старые кастомные значения элементов
  сознательно теряются.
- Создать `demo-typography.md` (состав — раздел «Контрольный лист»).
- Приёмка: существующая установка после апдейта сразу показывает колонку 740 и новые
  дефолты; слайдер работает; full width возвращается через 0. Контрольный файл на
  600/900/1400 pt ширины окна — колонка центрируется, ничего не ломается.

## 11.1 Body rhythm

Файлы: `VisualCoordinatorPresentation.swift`, `EditorTheme.swift`.

- Per-element leading (см. шкалу): body/списки/цитаты 1.30; строки code block 1.20;
  заголовки получают свой в 11.2. **Не** трогать: table islands (там `minimumLineHeight`
  резервирует высоту грида) и attachment-абзацы — display-math и изображения (глиф сам
  задаёт высоту; проверить, что multiple не режет его и не даёт скачков базовой линии).
- paragraphSpacing 6 → 8; списки: item spacing 2 → 3, отступ после последнего элемента
  списка 6 → 8.
- Смешанная строка (body + inline-код меньшего кегля + ссылка + bold) не должна «дышать»
  по высоте между соседними строками абзаца.
- Приёмка: контрольный файл (фикс. условия) + при columnWidth=0 вручную — ширины
  600/900/1400. Settings ▸ spacing масштабирует пропорционально.

## 11.2 Иерархия заголовков

Файлы: `EditorSettings.swift` (`ElementStyles.init`), `EditorTheme.swift`,
`VisualNSTextViewDrawing.swift`, `VisualCoordinatorPresentation.swift`.

- Новая шкала/веса/leading из таблицы + оптические капы приращения (H1 ≤ base+16,
  H2 ≤ base+10, H3 ≤ base+6) и floor моно-кода — капы живут рядом с `headingSize(_:)`,
  а не в UI.
- Интервалы before/after из шкалы, плюс **парное правило**: у заголовка, идущего сразу
  за другим заголовком, before сокращается (≈50%), чтобы H1→H2 не давал дыру. Механика
  соседей уже есть в presentation pass (`paraScan`).
- Обязательные проверки пар ритма из контрольного файла: H1→H2, H2→H3, заголовок→список,
  список→заголовок, цитата→заголовок, заголовок в начале документа (before = 0 уже есть).
  Многострочный H1/H2 при колонке 740 — leading 1.12 не должен выглядеть рыхлым.
- **Убрать дивайдеры под H1/H2** (`headingDividers` + отрисовка); `headingDividerColor`
  удалить вместе с draw-кодом.
- Setext-заголовки подтягиваются автоматически (те же `.heading`).
- Приёмка: контрольный файл при базе 12, 15, 20 (+ sanity 9/40): иерархия читается без
  линий, H1 не «чернее» страницы, на 40 pt шкала сжата капами, на 9 pt код не мельче body-
  читабельности.

## 11.3 Inline-семантика и состояния

Файлы: `VisualCoordinatorPresentation.swift` (`applyDerivedInlineDecorations`),
`EditorTheme.swift`, `VisualNSTextView.swift`/`VisualNSTextViewDrawing.swift` (состояния).

- **Inline-код, шаг A**: цвет = `textColor` (дефолт `inlineCodeColor` перестаёт быть
  красным; пикер в Settings остаётся), фон — плоский `.backgroundColor`
  `ghAlpha(light: 0.055, dark: 0.09)`, кегль по шкале с floor. Math-runs — тот же
  нейтральный тон. Просмотр пользователем на плотном техническом тексте (контрольный файл
  + файл со скриншота-1).
- **Inline-код, шаг B** (только после просмотра A): решение «pill или плоский фон».
  Если pill — отрисовка скруглённых (r≈4) плашек по runs в `drawBackground` с
  горизонтальным паддингом ~3pt (механика как у code panels), на переносе строки — две
  аккуратные плашки. Решение фиксируется одно, в HISTORY; performance-соображения могут
  отменить pill, но тогда baseline — плоский фон, а не «два допустимых вида».
- **Ссылки** (обычные и wiki): accent-цвет без постоянного подчёркивания. Обязательно
  минимум одно дополнительное состояние-аффорданс (link-hover-механики в Visual сейчас
  нет — mouse tracking используют в основном таблицы):
  - underline при каретке внутри ссылки (дёшево: presentation pass знает selection), и/или
  - underline при ⌘-hover (курсор навигации уже есть), и/или
  - полноценный hover, если tracking окажется дешёвым.
  Рекомендация: каретка-внутри + ⌘-hover.
  **Accessibility**: при включённом Increase Contrast
  (`NSWorkspace.accessibilityDisplayShouldIncreaseContrast`) постоянное подчёркивание
  возвращается — цвета может не хватить.
- **Done-задачи**: серый `secondaryColor` без strikethrough (перечёркивание остаётся только
  у явного `~~del~~`). Плагинные task-токены с `state.strikethrough` — по конфигу токена.
- Приёмка: технический текст перестал «рябить»; ссылка различима не только цветом
  (продемонстрировать состояние); Increase Contrast проверен; round-trip и paste-тесты
  зелёные.

## 11.4 Списки, цитаты, code blocks

Файлы: `VisualNSTextViewDrawing.swift`, `EditorTheme.swift`,
`VisualCoordinatorPresentation.swift`.

- **Маркеры списков**: точка меньше (≈3.5–4pt), нейтральная (`markerColor`/`secondaryColor`
  вместо accent); номера ordered — `monospacedDigitSystemFont`, `secondaryColor`,
  выравнивание по правому краю колонки маркера. Чекбоксы остаются accent (интерактив),
  выравниваются по cap-height первой строки — перепроверить после нового leading.
- **Blockquote**: бар — нейтральный серый (тон `separatorColor`, чуть темнее), ширина
  3 → 2; wash `quoteBackground` → прозрачный; текст — `secondaryColor` (дефолт
  `elements.quote.color`). Callouts сохраняют цветной бар/иконку.
- **HR**: hairline 1px `separatorColor`, вертикальные отступы ≈16/16.
- **Code panel**: радиус 6 → 8, фон оставить; кегль листинга по шкале; внутренние отступы
  панели перепроверить после 11.1.
- Приёмка: контрольный файл + файл с вложенными списками/цитатами; цитата со скриншота
  (стр. 112) выглядит спокойной цитатой, а не панелью-алертом.

## 11.5 Таблицы

Файлы: `VisualCoordinatorPresentation.swift` (`.tableCell`), `VisualNSTextViewDrawing.swift`
(island-грид), общие константы — в `EditorTheme`.

- Сетка: только горизонтальные hairlines между строками; header — semibold, линия 1pt
  снизу, без заливки (если header теряется — едва заметная `ghAlpha(0.03/0.05)`).
  Native: `NSTextBlock.setWidth(_:type:for:edge:)` по-рёберно; island: колоночные
  сепараторы не рисуются постоянно.
- **Вертикальный guide при интерактиве**: при hover границы колонки и при drag/resize
  island-грид показывает временную вертикальную линию — связь текста с колонкой не
  теряется, drag-ручки и hit-testing живут.
- **Числа и даты**: tabular figures (`monospacedDigitSystemFont`) в ячейках; явные
  alignment-маркеры markdown уважаются как сейчас.
- Минимальная высота строки ≈28pt при базе 15 (масштабируется), паддинг ячейки 6 → 8–9.
- Длинная ячейка: wrap (не clip); отдельная проверка на узком Split (~500pt на панель) —
  таблица остаётся читаемой, связь ячейка↔колонка не теряется без вертикальных линий.
- Зебра `tableRowBackground` — выключена по умолчанию (константа остаётся).
- Native и island: одинаковая иерархия и токены (общие константы), функциональные различия
  допустимы.
- Приёмка: контрольная таблица (числа/даты/длинная ячейка) + таблица больше
  `maxNativeTableCells` (island), обе в полной ширине и в узком Split; редактирование,
  drag строк, resize колонок живы; тесты таблиц/буфера зелёные.
