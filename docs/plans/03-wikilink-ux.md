# План 03 — Wiki-link UX: автодополнение и переход к заголовку

Статус: не начат
Зависимости: 02 (ссылочный индекс — источник кандидатов)
Закрывает хвост из CLAUDE.md: «wiki-link autocomplete/heading scroll».

## Цель

1. **Автодополнение** при наборе `[[` в Source и Visual: список файлов workspace
   (имя, title, aliases), после `#` — заголовки выбранного файла.
2. **Переход к заголовку**: `[[Файл#Заголовок]]` открывает файл и скроллит к заголовку
   (сейчас `navigateToWikiLink` открывает файл без позиционирования — проверь текущее
   поведение перед началом).
3. **Подсветка неразрешённых** wiki-links в Source (визуальный маркер «цель не найдена»).

## Контекст и существующий код

Прочитай: `CLAUDE.md`, `docs/HISTORY.md` (wiki-links, Source-подсветка, Visual-атрибуты).

- `EditMD/EditMD/Views/WikiLinkResolver.swift` — `resolve`, `navigateToWikiLink(target:from:)`,
  `nearestVaultRoot`. Точка входа перехода — сюда добавляется позиционирование на заголовок.
- `EditMD/EditMD/Editor/WikiLink.swift` — `parseWikiInner` уже выделяет `heading`.
- `EditMD/EditMD/Editor/MarkdownOutline.swift` — парсинг заголовков: и для кандидатов
  после `#`, и для поиска якоря при переходе. Сопоставление заголовка — case-insensitive,
  с нормализацией пробелов; правило зафиксируй в одной чистой функции + тесты.
- `EditMD/EditMD/Editor/SourceTextView.swift` — Source-редактор: перехват ввода, позиция
  каретки, попап. `EditMD/EditMD/Editor/VisualNSTextView.swift` / `VisualTextView.swift` —
  то же для Visual.
- `EditMD/EditMD/Editor/MathEditorPopover.swift` — существующий образец попапа у каретки
  (позиционирование, dismiss); автодополнение делай тем же способом (NSPanel/popover у
  прямоугольника каретки).
- План 02: `LinkIndex` знает все файлы; frontmatter-aliases берутся из
  `parseFrontmatterProperties` (`Editor/Frontmatter.swift`) при скане индекса —
  если план 02 их не сохранил, добавь поле в записи индекса.
- Открытие файлов — через существующий роутинг AppState (как это делает
  `navigateToWikiLink`); не открывай окна напрямую.

## Архитектурные решения

- **Общий движок, два хоста.** Чистый компонент
  `WikiCompletionEngine` (новый файл `Editor/WikiCompletion.swift`):
  вход — текст, позиция каретки; выход — состояние
  `{ активна ли сессия, запрос, диапазон замены }` + `func candidates(query:) -> [Candidate]`.
  Полностью тестируемый без UI. Хосты (Source/Visual) только рисуют попап и применяют
  выбор.
- Триггер: набранные `[[` без закрывающих `]]` на той же строке до каретки. Esc закрывает
  сессию; `]]`, пробел в начале запроса или уход каретки из диапазона — завершают.
- Кандидаты: ранжирование — точный префикс имени файла > префикс title/alias > подстрока;
  максимум ~20; отображение «имя — относительный путь». После `#` — заголовки цели
  (для текущего файла — из открытого документа, для чужого — прочитать файл в фоне,
  кэш по (url, mtime)).
- Применение выбора: вставка `Цель]]` (или `Цель#Заголовок]]`) **через обычный путь правки
  текста** редактора (undoable, с корректными typing attributes). В Visual вставка идёт в
  обычный текст; внутри `codeBlock`/`tableCell`/`.raw` автодополнение **не активируется**
  (тот же контекстный guard, что у paste — переиспользуй его, не копируй).
- Переход к заголовку: `navigateToWikiLink` после открытия файла передаёт heading в
  AppState/редактор; позиционирование — существующим механизмом `onJump`
  (Outline уже прыгает по заголовкам — переиспользуй его путь). Если файл открывается
  впервые, прыжок после загрузки документа (одноразовый pending-anchor в AppState).
- Неразрешённые ссылки в Source: presentation-атрибут поверх существующей подсветки
  (пунктирное подчёркивание/приглушённый цвет). Layout не меняется → допустим
  temporary attribute; если решишь менять что-то влияющее на layout — только storage
  attribute (инвариант CLAUDE.md). Резолюция — по `LinkIndex`, с дебаунсом; не резолвить
  синхронно на каждый keystroke.

## Этапы

### Этап 1 — движок автодополнения (без UI)

`WikiCompletion.swift` + тесты: детект сессии, диапазон замены, запрос, ранжирование
кандидатов, режим `#заголовок`.

### Этап 2 — попап в Source

Попап у каретки (образец MathEditorPopover): список, ↑/↓, Enter/Tab — применить,
Esc — закрыть, клик мышью. Вставка через undoable-путь. Клавиатурные события не должны
утекать в текст, пока попап открыт.

### Этап 3 — попап в Visual

Тот же движок; контекстный guard (не в code/table/raw). Проверка round-trip: вставленный
wiki-link сериализуется в тот же markdown (`AttributedToMarkdown`).

### Этап 4 — переход к заголовку

Нормализация сопоставления заголовков (чистая функция + тесты), pending-anchor при
открытии, скролл + мигание/подсветка целевой строки (если есть существующий механизм
подсветки строки — переиспользуй). Работает из Source, Visual и Preview
(Preview-клики идут через JS bridge — проверь, что heading доходит и туда).

### Этап 5 — маркер неразрешённых (Source)

Дебаунс-резолюция видимых wiki-links, temporary attribute, очистка при исправлении.
Обнови и Preview при желании пользователя — **нет**, вне scope: Preview не трогаем.

## Тесты

- Движок: триггер/не-триггер (внутри code fence, inline code, `]]` уже закрыт, `[` один),
  диапазон замены с кириллицей/эмодзи (UTF-16!), ранжирование, `#`-режим.
- Нормализация заголовков: регистр, лишние пробелы, `**жирный**` внутри заголовка,
  дубликаты заголовков (берётся первый).
- Round-trip Visual: текст с вставленным через автодополнение линком → markdown → без изменений.
- Переход: `[[Файл#Раздел]]` в уже открытом файле и в закрытом (pending-anchor).
- Существующие wiki-тесты не сломаны.

## Критерии приёмки

- `[[` в Source и Visual открывает попап; выбор вставляет корректный линк; Esc чисто
  закрывает; в code fence попап не появляется.
- `[[Файл#Раздел]]` — клик открывает файл и позиционирует на заголовок во всех трёх режимах.
- Неразрешённые ссылки визуально отличимы в Source и перестают подсвечиваться после
  создания целевого файла (после реиндекса).
- Никаких фризов при наборе в большом файле.

## Инварианты и запреты

- Один парсер/резолвер wiki-links (см. план 02); движок автодополнения их переиспользует.
- Вставка только через undoable-путь редактора; никаких прямых мутаций NSTextStorage
  в обход сериализации.
- Контекстные guards общие с paste-механикой — расширяй существующий guard.
- Не добавляй файлов вне `Editor/`/`Views/`; `xcodegen generate` после добавления.
- Попап не должен вызывать modal-циклов и не должен ломать first responder редактора.

## Верификация

Сборка/тесты (см. план 01). Глазами: демо-workspace с 3–4 файлами и заголовками —
автодополнение, `#`-дополнение, переход, мёртвая ссылка. Проверить обе темы и Split.
